## 3. 失败机理：到达时刻被一再推迟

在开发块失败回合中，逐决策计算"决策时刻 + τ_eff"（计划的到达时刻）。例如 30k 的 295001：

- 计划到达时刻依次为 109 → 126 → 178 → 212 → 265 → 300 → 362 s；
- 期间新计划 115 次；
- 300 s 时超时，结束时距离 6.4 m。

5k 的同一开局表现相同。

相比之下，15k 和 20k 的策略主要请求"更早到达"：G★ v0.4 无法提前时就保持原计划（`kept:no_earlier` 分别为 328 次和 282 次），这两个检查点都是 16/16。

25k 和 30k 时，"推迟"重规划又多于"提前"：

| 检查点 | 推迟次数 | 提前次数 |
|---|---|---|
| 25k | 299 | 215 |
| 30k | 277 | 212 |

## 4. 根本原因：任务中可学的增益远小于学习噪声

| 量 | 数值 | 来源 |
|---|---|---|
| 规则 rv:0（最早可行）在 R1 32 个开局上的平均折扣回报 | 80.49 | `evidence/T1_R1_pass2` |
| 逐开局在 6 种到达择时规则中取最好者的平均回报（择时上限的近似） | 81.15 | 同上 |
| 择时选择能带来的最大增益 | **约 0.7** | 两者之差 |
| 开发块上未训练策略 vs 规则 | 81.02 vs 81.09 | 包内 0k；`evidence/T1_dev_rule_295000` |
| 训练中 critic 的 TD 损失（每个 critic 的均方误差，SB3 计法） | 均值 19–27，中位数 11–15 | 包内 `*_cf_stats.json` 的 `real_loss` |
| 对应的 TD 误差量级 | 约 3.5–5 个回报点 | 上一行开方 |

结论分三点。

**(a) 择时几乎没有可学的增益。** 在当前任务、奖励和 G★ 下，最早可行到达加保持计划已接近最优。逐开局挑最好的择时也只多约 0.7 个回报点（κ 固定为 0.7，κ 带来的增益未计入）。

**(b) 学习信号被噪声淹没。** critic 的 TD 误差（约 4 点）是可学增益的 5 倍以上。在保持带内，所有动作的效果完全相同，Q 对 a0 是平的；actor 的动作在噪声驱动下漂移，一旦漂出保持带就会触发重规划。

**(c) 推迟的代价被延迟且不对称。** 每推迟一次只多花约 0.1–3 个回报点。真正的惩罚（超时 −100）要到 300 s 才出现，需要经过一百多步自举才能传回。另外，"更晚"的计划总是可行、总会被 G★ 接受；"更早"的请求则常被拒绝而保持原计划。因此动作漂移会累积成净推迟，最终导致超时。

由此可得：

- 本轮训练"没有明显改善"，**不是实现错误**，也**不是 M1 辅助项特有的问题**。在当前设定下，SAC 对到达择时**本来就没有可以学到的显著收益**，只会把方差和失败模式（推迟）带进来。
- 本轮停止规则以 0k 为基线、改善门槛为 +2.0。而择时上限只比基线高约 0.7，所以这条规则在回报上不可能判出"改善"；25k 和 30k 确实比 0k 差得多，停机本身是对的。门槛的设定是上层的失误，这里如实记录。

## 5. 对研究主张的影响

- 开发块上超过 Pure（11/16，0.91）的全部是 G★ 加共享 MPC 这套架构的贡献，而且第 0 步就已达到。这一点在"规则不可替代"的表述上必须如实报告（HANDOFF 第 1 节）。
- 在当前任务设定下，M0 或 M1 的学习都无法展示"学习相对规则的收益"。M1−M0 的耦合增量没有可以体现的空间。继续调参、增加步数或种子，都**回答不了**"学习是否有益"。
- 方向调整由研究层（用户与讨论窗口）决定。本审查不提出新的任务或奖励。

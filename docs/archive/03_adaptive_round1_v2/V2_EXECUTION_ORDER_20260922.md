| 棘轮 | 完成 | 平均 Δv | 平均存活 | 失败模式 |
|---|---:|---:|---:|---|
| 开 | 0/8 | 6.717 | 300.0 s | 全部超时 |
| 关 | 0/8 | **12.549** | 161.2 s | **6/8 距离失败** |

- **「8/8 → 0/8」在本任务复现不出来 → 该声明作废，不得再引用。**
- 该探针**在完成率上不可分辨**（0 对 0），所以也不能反过来说棘轮无害。
- **可分辨的是代价**：去掉棘轮燃耗翻倍、超时变距离失败 → **参考抖动真实且严重**。
- 严格地说，它只证明了"**在旧的 blend 参数化下**完全取消棘轮会抖"。V2 换参数化，
  所以要继承的是"**抑制抖动**"这个意图，不是 `max(历史, 本次)` 这个实现。

## 4. V2 设计：已拍定的五条

### 4.1 高层任务状态拆成两根轴

`z = (ρ, c)`：
- **ρ** = 距离推进 / 暂存半径（**单位 m**）；
- **c** = 同步承诺 / 参考从惯性暂存向体固连捕获几何过渡的程度（**无量纲，0–1**）。

现在的病根是**一个 blend 同时承载这两件事**：从 15–28 m 出发，想"靠近"就必须提高 blend，
提高 blend 又意味着"更强地追随旋转位姿"，**策略无法表达"先靠到 8 m，但别急着同步"**，
只能把 blend 推到 1。

### 4.2 不用绝对棘轮，用**不对称限速**

- 两根轴每步的变化量都限幅；
- 同步轴**往回退的限幅小于往前推的限幅**（能退，但退得慢）。

这样"捕获阶段总体越来越同步"的物理语义保住了，`①` 实测的抖动被限速压住了，
而且**任何一步都不可能锁死未来**。

**不要**继承 `blend = max(历史, 本次)`。

### 4.3 基线保底从动作层移到架构层

取消「RL 零动作 = Pure MPC 逐位」。新的硬地板是：

> **强制拒绝所有 learned proposal → 整条闭环逐位等于 Pure MPC。**

**必须写成自动测试，继续 measured not asserted。**
这条不补上就等于丢掉唯一的硬保证——不许先换后补。

### 4.4 拆轴之后要保住几何可行性，但**不得引入新硬约束**

拆开之后有些组合物理上不合理，例如"半径 3 m + 承诺 0%"= 沿冻结惯性方向距目标中心 3 m,
**极可能落在 keep-out 里**。所以联合映射要带几何保护。

但**不得**演化成新规则：
- 不加 hard opportunity window；
- 不加远场走廊 / far-range legality；
- 不加相位合法性门；
- `c = 1` **不应**自动让距离轴失效或直接等于 3 m 终端位姿。

只保留原任务语义：不进 keep-out；terminal / corridor 只在原本生效区域按原规则处理。

### 4.5 两根轴**不要**直接拼成未归一化的二维方向

ρ 的单位是 m、c 无量纲。以后真要做"方向 × 标量步长"时，**先定义归一化任务坐标或缩放矩阵**。
第一版用各轴独立限幅，绕开这个问题。

## 5. 为什么第一版**不**接 governor（两条实测理由）

设计上的长期方向是"高层给方向、下层给允许推进幅度"（Tartaglione 2024 的结构）。
**但第一版不做**，理由是实测的：

### 5.1 算力

h35 单步 MPC 的 p95 已是控制周期的 **0.77 倍**——一次求解吃掉四分之三预算；
h50 试过，300 步里 269 步超时，已废。仓库里 AC4MPC 那半边被关掉的理由正是
"**双解 = 1.5 倍预算**"。**沿方向做一维搜索比双解更贵。**

"摊到 20 个控制步只有几个百分点"**不能当实时性保证**——额外求解仍然集中在某一个
0.1 s 控制帧上。所以 **V2 第一版不增加任何在线额外 MPC 求解。**

### 5.2 更要紧：那个"能不能走"的信号可能几乎不变化

正式评估里，Pure MPC 和两个模型的 **QP 无解次数都是 0、零推力回退也是 0**。
也就是说在这个任务上"解不出来"基本不发生。**如果 governor 的判据是"解不出来就少走"，
它会永远判"能走"，变成空壳**——而且训练跑完才发现，**和第一版死在同一种错法上**。

另外，真正能反映"紧不紧"的 `predicted_minimum_margin` 需要完整时域推演、
**只在 `runtime_diagnostics=True` 下存在**，而训练是关掉诊断的（仓库陷阱 2）。

**所以 governor 之前必须先做一次离线信号审计。**

## 6. Step 1：离线信号审计（你的第一个任务）

**目的**：只回答一个问题——

> **当候选任务推进变激进以后，至少有没有一个现成的 MPC 执行信号出现稳定、可解释的变化？**

**不改任务、不改训练、不改 reward。纯离线读数。**

### 6.1 状态从哪来

**不要**只用最终 V1 策略自己的 proposal——它已经塌回 nominal，提不出有意义的候选。
从已有 48 种子 rollout 里抽**代表状态**：建议 24 个决策点，覆盖不同初始距离、
不同目标相位、不同剩余时间。抽样规则写进产物里。

### 6.2 候选扰动怎么造

在每个状态上，人为构造少量候选任务扰动（不是策略给的）：

- 距离：**前进小步 / 前进大步 / 后撤小步 / 后撤大步**；
- 承诺：**增加小步 / 增加大步 / 减少小步 / 减少大步**。

共 8 个候选 + 1 个不动（基准），每个状态 9 次求解。24 × 9 = 216 次单步求解，很快。

### 6.3 读哪些信号

现成的：`maximum_successful_slack`（注意仓库陷阱 3：**只从成功求解的步读，或与 fallback
标志配对**）、总松弛、目标函数值、执行器用量。

离线可**额外打开** `runtime_diagnostics=True` 读 `predicted_minimum_margin`——
但它此时**只作为 oracle**，不代表训练时能在线用。

### 6.4 预注册判据（先写下，再看结果）

一个信号算"有信息量"，需要同时满足：

1. **单调性**：在 **≥ 70%** 的抽样状态上，该信号随候选扰动幅度**单调变化**
   （至少在一个扰动方向上）；
2. **可分辨性**：该信号在候选区间上的变化幅度，**大于它在同一状态上重复求解的自身波动**
   （所以每个状态要重复求解 2–3 次估一下波动）。

结果分三种：

| 结果 | 结论 | 下一步 |
|---|---|---|
| 有**便宜**信号满足判据（松弛 / 目标值 / 执行器用量） | governor 有地基 | 记录下来，**但第一版仍然不接**，等 V2 学起来再插 |
| **只有** `predicted_minimum_margin` 满足判据 | **唯一有用的信号在线用不起**（要完整时域推演） | 这本身是一条结论，写进报告；第一版固定限速 |
| 没有信号满足判据 | governor 无地基 | 第一版固定限速；不要硬做 |

**三种结果都不改变 V2 第一版的做法（固定不对称限速）。** 审计是为后面那一步准备，
**不是 V2 的前置门**——所以它跑完就写报告，不要卡住 Step 2。

## 7. Step 2：先写红测试（不训练）

V1 的教训是**没有事先写下判据**，结果接口一半是死的、跑两天才发现、
而且发现之前所有指标都健康。所以先写测试，全部会红，然后照着实现。

用 `pytest.mark.xfail(strict=True)`，套件保持绿；修好之后 strict xfail 会转报错，
**强制删标记**——缺陷既不能被悄悄绕过，也不能被悄悄修掉。

| 测试 | 验收判据（要写成能跑的断言） |
|---|---|
| **T1 距离轴有效** | 在非物理饱和区内，不同的合法距离指令产生**可观测不同**的任务参考；**且允许有限后撤**（ρ 可减小） |
| **T2 同步轴有效** | 不同同步指令产生不同 progression；**任何单次动作都不能永久锁死后续自由度**（施加最大同步指令后，后续指令仍能改变参考） |
| **T3 回退无副作用** | 一次 proposal 被拒绝**只影响当前这一步**，不得改写不可逆任务状态（拒绝之后，下一步的暂存请求仍然有效） |
| **T4 架构级基线地板** | **强制拒绝全部 proposal → 整条闭环逐位等于 Pure MPC**（对照 `--control desired_pose`，`max |Δwrench| = 0`） |
| **T5 几何可接受性** | 任意合法 (ρ, c) 组合产生的参考**不得进入 keep-out**、不得违反原任务定义；**且这条不能变成新的远场硬走廊** |
| **T6 限速器可解释** | 输入输出单调、**无大面积死区**：等距扫描输入，产生的不同输出数量必须等于输入点数（这条直接对着 V1 的"21 个输入 → 11 个输出"） |

**T6 就是 V1 那个病的通用化版本**，务必写死。

## 8. Step 3：实现 V2（冻结清单）

实现时**只动高层动作接口与参考生成**。以下全部冻结，一个字不改：

- **reward**（单位已修正，不要再动）；
- **SAC 超参**（学习率 1e-4、熵系数固定 0.005、tau、batch、网络）；
- **MPC**（horizon 35、Q/R、走廊、终端、容差）；
- **任务参数**（几何、约束、时限、初始分布、翻滚率）；
- **执行器权限、控制周期**。

结构要按"以后可插 governor"的方式搭：

```
SAC 期望任务状态 → 推进限制器（第一版 = 固定不对称限速）→ 实际任务状态
                                                        → 平滑参考生成 → MPC
```

第一版限制器 = 各轴独立限幅（`Δρ` 与 `Δc` 分别 clip，同步轴退得比进得慢）。
以后把限制器整体替换成 MPC-informed governor 时，**SAC 动作语义和参考生成都不用改**。

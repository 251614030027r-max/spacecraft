## 0. 一句话总览（用户原文）

当前研究已经不再只是"用 SAC + MPC 完成快速翻滚非合作航天器预捕获任务"。

经过多轮机制验证、接口修复和对照实验，论文正在收敛到一个更一般的问题：

> **在长时域、强约束控制任务中，有限预测时域的 MPC 与学习型长期任务策略，在不同状态下的长期闭环表现不同。如何根据它们各自的长期后续价值做状态相关的协调，并把高层任务意图可靠地交给短时域约束控制器去执行。**

框架的核心：

> 长期任务策略学习 + 任务意图到局部参考的正确实现 + MPC 约束执行 + 长期后续价值驱动的策略协调

当前最明确的方法瓶颈：

> **如何可靠地估计"从当前状态继续执行某个闭环策略"之后的长期结果，并让这种估计足以支撑协调。**

这和"重新设计一个更复杂的 SAC 网络"不是一回事。

【上层补充】第二轮之后，这个瓶颈被刻画得更具体了：
- 价值要在**关键状态**上分得清"这次谁会成功"。关键状态指一方成功、另一方失败的状态，协调只在这些状态上起作用；
- 现有的标量价值回归在这些状态上的判对率接近 50%（第 13 节）；
- 另外还冒出一个一阶问题，必须先讨论："学习的任务策略"本身，比不含学习的平缓推进脚本多给了什么？（第 14 节）

## 1. 任务与工程背景

**任务**：快速翻滚非合作目标航天器的预捕获接近。它同时具备以下特点：
- 六自由度刚体相对运动；
- 高保真真值环境；
- 目标持续自由翻滚；
- 有限的推力和力矩；
- 视场、避碰、入口几何、终端速度与姿态等约束；
- 数百秒的任务时间尺度，与数秒的 MPC 预测时间尺度明显分离。

**参数**（以代码为准：`env/task.py`、`precapture_adaptive_capture_environment_config()`）：

| 项目 | 取值 |
|---|---|
| 质量 | 追踪器约 106 kg，目标约 225 kg |
| 轨道 | 500 km、倾角 45° 圆轨道 |
| 真值积分 | RK45（中心引力 + 二阶矩 + 重力梯度 + J2） |
| 控制周期 | 0.1 s |
| 执行器限幅 | 推力 ±5 N/轴，力矩 ±0.6 N·m/轴 |
| 目标翻滚 | 标称 0.041231 rad/s（约 2.36°/s，周期约 152 s） |
| 回合时长上限 | 300 s；距离超过 30 m 判失败 |
| 初始距离 | 约 15–28 m（adaptive 任务配置） |
| 避碰 | keep-out 半径 2 m |
| 入口平面 | 距目标中心 6 m（`entry_port_axial_distance_m = 4.5`） |

| 走廊与视场 | 走廊半角 35°，视场半角 50° |

`Λ = ω·r/v_max > 1` 在大部分距离范围内成立，所以追踪器不能停着等，必须持续跟着目标转。这是本任务区别于平移交会、也区别于参考文献工况的物理原因。

## 2. 最初的问题与后来的转变（用户原文）

早期目标：在高保真快速翻滚目标接近任务中，把 RL 与 MPC 结合，提高完成能力，同时保留约束执行能力。
早期故事：RL 擅长长期决策，MPC 擅长短时域约束控制，所以 RL 在上、MPC 在下。

后来的实验证明，这句话只能解释"为什么值得组合"，构不成论文创新。而且一些原本归功于"长期决策"的收益，其实混入了参考接口、评估器、终端门等工程因素。

研究线因此从"怎样把 SAC 和 MPC 耦合起来完成任务"，转向"两个异构闭环策略在不同状态下的长期结果不同，怎样评价并协调它们"。**这是本项目最重要的思想转变。**

## 4. V1：短残差式耦合被关闭（用户原文，略补）

- **结果**：三个从零训练到 60k 的种子，最终都接近 Pure MPC（36/48），没有稳定的救回。实际干预比例只有 0.114% 和 0.484%，所以**耦合根本没被测到**。
- **根因（R5）**：`a_commit = clip(1 + 2r)` 把所有 r ≥ 0 映射到同一个参考，半个通道的梯度恒为零；再加上承诺棘轮，决策被压缩到第 0 步。
- **留下的认识**：学习层如果只是修正 MPC 当前的动作或未来几秒的行为，很难形成需要的长期任务能力。
- **禁止的两种说法**："耦合无效"（它根本没动作过）；"基线保持已验证"（靠不动作达成的保持是恒等式）。

## 6. V3：从动作耦合转向长期策略协调（用户原文）

结构如下：
1. SAC 作为长期任务策略（`task_state_v3`：2 维动作 Δ推进、Δ承诺；42 维观测）；
2. MPC 作为短时域约束执行器（时域 35 步）；
3. 分别学习 V_L（继续学习策略）和 V_B（交给 Pure MPC）两个价值；
4. 按两者比较做状态相关协调：开局选择，之后最多单向交回一次，交回后不再回到学习分支。

保守规则（z = 1，各为 5 个头的集成）：
- 开局：μ_L − σ_L > μ_B + σ_B 时才选学习；
- 在学习分支上：μ_B − σ_B > μ_L + σ_L 时才交回。

**注意**：
- z = 1 只是工程规则；
- 集成的标准差不是严格的统计置信区间；
- 如果要理论化，需要另外建立误差或覆盖率的解释。

【上层补充】第二轮暴露出这条规则的一个**不对称**（第 13 节）：开局时"没把握就选 Pure"，是保守的；交回时"没把握 Pure 更好就不交回"，等于"没把握就留在学习分支"，这不保守。

## 8. 为什么参考路径成了关键问题（用户原文）

**旧接口的问题**：高层每 2 s 更新一次路标点，MPC 时域约 3.5 s，时域内对路标点做近似线性外推。但目标一直在转，对一个在惯性系里大致固定、在目标系里不断旋转的参考点，线性外推漏掉了旋转几何的曲率，由此漏算的加速度已接近单轴推力上限的量级。

**v3e 的修复**：在 MPC 的整个预测窗口内，按目标未来的旋转状态，把当前高层意图展开成与旋转几何一致的局部参考轨迹。

**三层职责要始终分清**：
- RL 决定"做什么"；
- 参考实现决定"怎样把意图连续、正确地表达给 MPC"；
- MPC 决定"在满足约束的前提下怎么控制"。

参考实现不是另一套任务决策器，也不是人工把整条最优路径写进去。

【上层补充】修复效果：同样在 50k，v3e 比 v3d 多耗的燃料下降了 55–75%（已入库 `eval/v3e/early_50k_readout.json`，SHA-256 `72d6548c…ef06`）。

## 9. 固定平缓推进对照如何改变了理解（用户原文，补数字）

结论：一个很简单的平缓推进策略，就能救回不少原本 Pure MPC 失败的开局。所以不能把 Pure MPC 的全部失败都解释成"MPC 缺乏长期策略"，其中相当一部分收益来自**正确的参考管理**。论文必须区分：
1. 参考管理（接口）的收益；
2. 状态相关的学习策略的收益。

`v3_nominal`（平缓推进）的定义：固定的平缓任务策略（学习分支按满速推进）+ 与学习策略相同的参考实现 + MPC。它回答"只把参考管好、不用状态相关的 RL，会怎样"，比只和 Pure MPC 对比更有说服力。

## 11. 安全结果如何理解（用户原文，补一点）

learned-only 有少量真值违规回合，已检查的共同特征：
- 所有完成回合都是零违规；
- 违规只发生在失败终止的那一步；
- 多是贴着视场或走廊边缘的轻微越界（归一化余量 −0.0001 到 −0.025）；
- 违规前通常已经发生过非法进入；
- 不是 QP 大规模崩溃造成的；
- Pure MPC 的失败以超时为主。

所以既不把它们当作代码故障，也不放松安全标准。**最终方法的真值违规回合数不得多于 Pure MPC（在 262000 块上是 0）。**

【上层补充】Pure MPC 在 270000 块上也有 1 次视场失败。所以"48 个开局里 1 次对 0 次"属于噪声量级。已完成各轮的判定照旧不改；**以后预注册安全门时，建议在更大的块上比较违规率**。这条需要和用户讨论后再写进新的预注册。

## 14. 【上层补充】第二轮之后的总审查：三个此前被忽略的事实

来源：`docs/V3E_STATE_REVIEW_20260930.md`。全部是用 262000 块交付 JSON 算的，属于探索，**需要落成产物才能进论文**。

1. **在当前接口下，学习策略比不过平缓推进脚本**。262000 块上，三个学习模型的平均完成数是 37.7，平缓推进是 40；只有 262420（42）比它多。审稿人一定会问"学习比满速推进脚本多给了什么"。目前平缓推进只在这一个块上跑过，所以这还不是结论。
2. **比 Pure MPC 慢将近一倍，是接口结构造成的**（`env/hybrid_env.py`）：
   - 参考点每次决策最多移动 0.40 m（`v2_reference_step_max_m`），近场半径下限 6.5 m，要到承诺度 ≥ 0.8 才放开；
   - 平缓推进有 87% 的决策卡在这个上限上，第 44 个决策（88 s）才达到承诺度 0.8；而 Pure MPC 完成整个任务平均只要 95 s；
   - 学习层在这个接口里**只能比满速推进更慢**。Pure MPC 那种"直接飞过去"的做法，不在它的动作空间里；
   - **来历更正（2026-09-30，经新窗口核对 `docs/V2_RATE_LIMIT_DECISION_20260922.md` 和 `docs/V3E_PLAN_AND_EXECUTION_ORDER_20260927.md` 检测 C）**：
       - 0.40 m 上限并不是为 QP 健康加的。它是 09-22 四档扫描里最宽的一档，目的只是给原本没有上界的承诺弧长加一个界。当时的扫描趋势是越紧越差，更宽的 0.60 / 0.80 两档没有测。
       - 那份文件自己写了一个回头条件："若训练中限速器持续顶着上界，再回来调这个数"。这个条件早已满足：平缓推进有 87% 的决策顶在上界上，学习策略为 60%–70%（这两个比例是上层根据 60k 评估 JSON 算的，属于探索数字）。
       - 只有近场半径下限有可行性测量依据：去掉下限时，零推力回退率为 1.9×10⁻³，高于健康门 1×10⁻³。

   所以时间和燃料的劣势不是"可接受的代价"。
3. **互补主要发生在两个非学习控制器之间**：
   - Pure ∪ 平缓推进 = 46/48，再加上学习模型也只到 46–47；
   - 在 Pure 失败的 11 个开局里，平缓推进救回 9 个，学习模型最多救回 8 个；
   - 这与项目历史上的两次观察一致：T12 中学习层持续改写参考，敌不过固定设定点；第一轮脚本分段实验中，按开局选择的上限是 +4。

**这些事实与主线的关系**（上层理解，供讨论）：
- 它们**不否定**用户的主线："异构闭环策略的长期继续协调"。平缓推进本身也是一个闭环继续策略；P2′ 也已经证明，价值准确时协调是有效的；
- 它们动摇的是两个具体环节：
  - (a) 被协调的"学习任务策略"在现有接口下的独立贡献还没有被证明；
  - (b) 学到的价值在关键状态上没有区分能力；
- 第 15 节第一层的"价值选择性能界"正好能刻画 (b)：选择不出错的条件是估计误差小于两个分支之间的真实差距。关键状态判对率约 50%，说明在那些状态上误差 ≥ 差距。**这是理论与实验的天然连接点**，不需要回避。

## 15. 论文思想的核心转变与数学工作（用户原文）

**最初的故事**："快速翻滚目标很难，MPC 只能看几秒，RL 能看长期"。问题是太任务型，也太像普通的分层 RL–MPC。
**中间的故事**："SAC 生成长期策略，MPC 负责约束执行，再用价值做动态权力分配"。问题是太泛，容易和安全回退、残差控制、一般的策略切换混在一起。
**当前的故事**：有限预测时域的约束 MPC，无法只凭局部预测评价不同长期闭环策略的最终结果；学习型长期策略与 MPC 的相对优势又依赖于状态。所以问题不是固定选一个控制器，而是**如何评价并协调多个异构闭环策略的长期继续**。

航天器任务是验证载体，不是创新来源。

**四层数学工作**：
1. **价值选择性能界**：设估计误差 |V̂_i − V_i| ≤ ε_i，研究什么条件下一定不会选错，以及所选策略相对"精确选择"的性能损失上界。这可以解释 M6、价值排序和不确定性裕量。
2. **保守的、考虑不确定性的选择**：μ − zσ 目前只是工程规则，以后可以升级为有覆盖率解释的区间，例如用独立校准或 conformal 方法。
3. **参考可行性**：意图 z = (ρ, c)，参考映射为 r = 𝓛(s, z, 目标未来的旋转)。可容许意图集定义为 𝒵_adm(s) = {z : 𝓛(s, z) 对当前 MPC 可跟踪、可行}。这样，步长上限、转速限制、近场可行性等工程量有机会统一成递归可行性条件。
4. **交回后的稳定性**：学习阶段保持状态有界且安全 → 交回时进入 MPC 可行域 → MPC 递归可行 → 终端区内 Lyapunov 下降。这比强行证明 SAC 全局渐近稳定更现实。

【上层补充】第 3 层与第 14 节第 2 点直接相关。现在的 𝒵_adm 是用"步长上限 + 近场半径下限"这种保守的内近似实现的，它把 Pure MPC 的快速做法排除在外。如果改用真正按 MPC 可行性定义的 𝒵_adm，它应当包含固定设定点（Pure MPC 本身就在这个参考上可行）。这可能是"接口时间下限"问题在理论上的正解方向。**这是推断，未经测量。**

## 16. 第二轮失败后的候选方法（用户原文 + 上层意见）

**用户原文**：如果标量的继续价值回归不稳定，优先考虑把"成败风险"和"成功后的任务代价"分开估计：
- p_i^succ(s) = P(成功 | s, π_i)；
- J_i(s) = E[时间/燃料代价 | s, π_i, 成功]；
- 甚至单独表示违规风险。

这样协调器可以先保证完成和安全，再比较成功情况下的效率。**这只是候选路线，不是既定方案。**

【上层意见，供讨论】
- 这个分解对准了第 13 节看到的问题：任务效用本质上是 +20 / −20 / 0 的多峰结局，回归把它压成了一个平均数。
- 但它**没有解决**学习策略"独立结局稀少"的问题：每个模型只有约 240 个开局，其中硬失败约 20 个。对确定性策略来说，每条轨迹只贡献一个独立结局。
- 对**非学习**的闭环策略（Pure MPC、平缓推进）而言，数据很便宜，可以大量采样。
- 另外，关键状态判对率约 50%，也可能说明"开局时就预测成败"本身很难（成败对目标相位敏感）。这一点需要测量，不能只靠推断。

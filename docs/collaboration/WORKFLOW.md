# 协作纪律（2026-10-15）

**工作链：研究层决定方法与授权 → 上层实现、必要测试并冻结 → 下层连续训练/评估与交付 → 上层集中审查。** 不把研究不确定性变成无限训练前核验。

1. **版本与授权。** [HANDOFF](HANDOFF.md)和[研究演进](RESEARCH_EVOLUTION_AND_COUPLING_DESIGN_20261012.md)供研究接续；[PROJECT_STATE](PROJECT_STATE.md)由上层维护，[CURRENT](CURRENT.json)由下层核验进程。用户最新授权与有效执行单优先；任何“已批准”字段均不能扩大授权。
2. **上层做什么。** 按选定方案修改科学代码；做与风险相称的核心测试、短冒烟、物理动作生效和M0/M2共同条件核查；排除可使实验无效的缺陷后，冻结SHA、配置、预算及可直接执行到交付的任务单。不得默认代跑大规模开发评估、规则扫描、长训或反复证明学习有收益。
3. **准入从简。** 检查程序可运行、可重载，动作/物理实现真实，安全裁判和公平对照未意外变化，实验可追溯。已有检查直接复用，出现明确阻断性错误才定向修复。学习增益、收敛和曲线形状应交由完整训练判定，不设为训练前硬门槛。
4. **下层做什么。** 按冻结单完成现场配置核验、必要基线、校准、完整训练、开发评估、监控、日志与模型哈希交付；自主处理不改变方法的进程、路径或监视器问题，不逐阶段请示。禁止自行改奖励、动作、网络、共享MPC、工况、种子、正式测试范围或预算。
5. **停止与结果。** 不因中期回报低、成功率下跌或短期策略坍塌停训；只执行当轮任务单中的技术停止条件。中期只读结果不触发额外方案审批。下层必须保留全检查点与失败样本，上层收到完整交付后审查增量、稳定性和失败机制；不因负结果自动加筛选或改场景。
6. **仓库纪律。** `collab/spacecraft`只修改`docs/collaboration/`；实验运行须使用冻结科学SHA。训练中不切换科学工作树；提交前fetch/pull --ff-only，禁止force-push。大文件可留本机并登记SHA。Git记已授权实验、结果、证据与交接，不把讨论作为事实。

**当前T1 v4第2.1版执行单不作追溯变更。** 该纪律用于压缩后续重复核验，而非降低真值安全、公平性或扩展既有授权。

# ECC 最终候选：认证中的远程入口候选（ECC_LE）

**状态（2026-11-18）：** ECC_EVT 未达到采用条件（224/288，低于原 ECC 的 236/288），按规则保留原 ECC。本文件在原 ECC 的基础上提出提高捕获率的改动，先于结果入库，采用规则不因结果修改。

## 1. 诊断（数据：`evidence/FORMAL/`）

- **ECC_EVT 没有坏，而是没有起作用。** 它与评价器同样只读策略观测、只用单步目标的"ECC w/o execution feedback"几乎完全相同：捕获率差 −0.3 个百分点 [−4.2, +3.5]，翻转 16 / 17。它比原 ECC 少的约 4 个百分点，等于取消六维执行反馈的损失（原来那部分为 +3.8）。
- **学习不是瓶颈。** 带认证的各组训练捕获率都停在 0.7–0.8。开发期紧急筛查中，固定意图 (1, 0) 加认证就能捕获 40/48。
- **入口机会集合有限。** 失败几乎都是超时：错过了可以兑现的经过。执行层只在距离 ≤ 12 m、端口–视线夹角 ≤ 35°、到达时刻 ≤ 60 s 时才尝试入口。直接入口规划则从远场按 20–220 s 的到达网格规划入口，开发期捕获 44/48。

## 2. 改动：远程入口候选

在认证中加入一个候选：用现有的入口规划器（不改），按到达网格 𝒯_L = {20, 30, …, 120, 140, …, 220} s 中不晚于 L 的时刻，从当前距离直接规划入口转移。

**只在最后一次可用的经过时尝试，以下条件同时满足：**

1. 实际飞行的意图（经认证后）在 48 s 预测内没有触发模式事件；
2. 端口在本阶段内（16 s）经过视线；
3. 错过这次经过，期限前不再有下一次：t + 到下一次经过的时间 + P > L。

可行就开始入口转移，由近场 MPC 执行，后续与普通入口相同（包括丢失后转为保持）；不可行就照常飞行原意图。其余部分全部与原 ECC 相同：评价器读执行反馈、认证规则、RWG、规划器、MPC、奖励、训练设置。

- **在方法中的位置：** 认证从执行器的机会中选择，机会现在包括两类：阶段意图触发的短程入口，以及最后一次经过时的远程入口。它不是新的学习组件。
- **学习器的角色不变：** 远程入口只在最后一次可用的经过时启用，此前的接近节奏和相遇时机仍由策略决定。

## 5. 运行与采用规则（事先固定）

- **A. 当晚只评估检验：**
  - 内容：第一轮 ECC 模型（种子 20–22）加远程入口，评估紧急任务 300000–300095；
  - 判据：合并捕获 ≥ 250/288（86.8%），且不安全不多于 1 次；
  - 达到就立即进入 B，否则停止并报告；
  - 配对检查：关闭远程入口重放种子 20 的前 12 个初始条件，必须与第一轮评估一致。
- **B. 训练 `ECC_LE`：** 种子 20–22，每个 5000 次决策，训练设置与原 ECC 相同；评估紧急任务与验证曲线。
- **采用 ECC_LE 作为论文最终方法，须同时满足（与第一轮原 ECC 配对）：**
  1. 合并捕获 > 236；
  2. 至少 2 个种子的配对捕获差为正；
  3. 平均真实回报 > 36.4；
  4. 不安全回合数不多于原 ECC 加 1。

  否则保留原 ECC。

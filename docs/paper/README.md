# 论文资料与写作取材指南

写论文时从这里**取事实**，表达按学术论文的写法另写。资料本身偏直白、偏细，有的地方为了准确会多写一句限定，这些不必搬进论文；名称与术语以 `facts/00_术语与符号.md` 为准。论文中不出现配置名、文件路径、提交号，也不出现"冻结""逐位等价"这类工程说法。

## 资料

| 文件 | 用于 |
|---|---|
| `latex/` | 论文初稿（IEEE TAES 模板）；编译方法见 `latex/README.md` |
| `facts/00`–`07` | 方法部分（术语符号 → 问题与建模 → 总体框架 → RWG → 执行层 → ECC → 学习算法 → 对比方法） |
| `facts/08_实验结果.md` 与 `evidence/PAPER_READOUT/` | 实验部分的全部数字与作图数据 |
| `BACKGROUND.md` | 引言：背景、两个问题、研究问题、贡献 |
| `References/README.md` 与 `References/`（仓库根目录） | 相关工作与表述参考；README 写明每篇用来做什么、不要声称什么 |

拿不准的事实回到代码核对：每个事实稿末尾的"代码对照"给出位置。

## 只在需要时查

| 文件 | 可用的内容 |
|---|---|
| `docs/DEAD_ENDS.md` | 开发期试过、未纳入方法的做法（讨论或附录用） |
| `docs/HISTORY.md` | 研究过程的时间线（不写进论文） |
| `docs/archive/EXPERIMENTS_ROUND1.md` | 第一轮正式实验的事先登记设计（已由实际结果取代） |

## 写作时不看

`CLAUDE.md`、`docs/engineering/`、注册表 JSON、协作分支的执行书与交付、各证据目录的原始文件。

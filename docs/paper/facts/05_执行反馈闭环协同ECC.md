# 05 执行反馈闭环协同（ECC）

ECC 处理理论问题：长期决策（学习的高层，每 16 s 一次）与短期受约束执行（执行层，0.1–2 s）之间的耦合。

**要解决的失配：**

- 高层意图的后果要经过执行层的规划、门限与跟踪才会兑现，其中关键的一环（端口经过时能否转入入口）只有执行层自己在短时域内看得清；
- 只用真实转移训练的高层，可能学不会在机会稀缺时及时把握这次窗口。

**ECC 的两种反馈：** 执行层通过同一个接口提供两种功能不同、互不重复的反馈：

1. **状态层：** 执行反馈 z_E 进入评价器；
2. **动作层：** 执行机会认证 𝒞 在训练与执行中修正意图。

学习本身仍是常规的离策略时序差分，只用真实转移。

## 5.1 状态层：执行反馈进入评价器

- **结构：** 评价器为 Q(o, z_E, a)，策略为 π(a | o)。z_E 的 6 项定义见第 02 节：三项机会判断，即到下一次经过的时间、入口可达性、经过后的期限余量；三项执行状态，即上一阶段的位置残差、速度残差、是否保持。
- **使用范围：** z_E 只在训练时由评价器使用。执行时只用策略，策略不读 z_E。
- **作用：** 在同一几何观测下区分"接管机会是否存在、意图是否被如实执行"，使评价器能表示更贴近真实后果的价值关系。
- **数学上能说的：** 增加条件信息不会缩小可表示的价值函数类。收益由实验说明，不主张无偏或必然更优。

## 5.2 模式预测

**问的是什么：** 在当前决策状态 x，对一个意图 b，执行层回答："如果接下来一直保持意图 b，自己会不会、在什么时候、花多少燃料离开阶段层，转入入口转移或末段下降？"

**怎么算：** 完全用执行层自己的规则与输入：

1. 从当前状态出发，按阶段层的规则（扫掠锥目标速度、阶段权限限幅、安全投影）与阶段规划器，逐阶段生成名义规划轨迹，至多 3 个阶段（H_p = 48 s）。规划被拒的阶段按原地保持处理；
2. 沿名义轨迹每 2 s 检查一次，与实际执行的规则相同：
   - 先查是否进入下降区；
   - 再查入口判定（距离、制动裕度、35° 夹角、到达不晚于 L）；
   - 对通过的到达时刻调用入口规划器，第一个可行者即为入口事件；
3. 目标姿态用恒速预报，惯量用估计值；
4. 预测在以下任一情形截止：达到预测时域、达到期限，或计划燃料用完剩余预算。

**输出：**

- ê(x, b) ∈ {0, 1}：是否发生模式事件；
- τ̂(x, b)：事件时刻，或预测截止的时刻；
- Δv̂(x, b)：到事件为止的阶段规划燃料，入口事件还要加上入口规划的燃料。

**它不是什么：**

- 不计算回报或价值，不对意图排序；
- 不使用历史数据，同一状态得到同一回答；
- 预测的事件是执行层模型下的模式切换，不等于捕获；
- 48 s 内无事件也不等于没有可行解。

**实现隔离：** 模式预测使用规划器的独立实例，不改变实际执行的求解器状态。有没有做这次预测，实际轨迹完全相同。

## 5.3 动作层：执行机会认证

**候选集：** 𝔅 是动作盒上的 3 × 3 均匀网格 {−1, 0, 1}²。每次决策（模式 S / H）时，对 𝔅 中 9 个候选和策略的原意图 a 各做一次模式预测。

**可认证候选集：**

  𝔅_c(x) = { b ∈ 𝔅 : ê(x, b) = 1，t + τ̂(x, b) + P > L，Δv_used + Δv̂(x, b) ≤ B_max }

三个条件依次是：

1. 会触发入口或下降；
2. 这是关键窗口：若错过这次事件，期限前已等不到下一整圈。t + τ̂ + P > L，P 为自旋周期；
3. 燃料够用。

**认证映射：**

  𝒞(x, a) = a，若 ê(x, a) = 1 或 𝔅_c(x) = ∅；
  𝒞(x, a) = 𝔅_c(x) 中按 (‖b − a‖₂, τ̂(x, b)) 字典序最小者，其余情形。

即：原意图自己会触发事件，或没有可认证候选，就照原意图执行；否则换成离原意图最近的可认证候选，距离相同时取事件更早者。

**作用范围：** 只作用于当前这一次宏决策，不强制后续决策保持。

**性质 E1（认证）：**

- 原意图在预测中会触发模式事件，或没有可认证候选时，执行原意图；
- 发生替代时，执行意图满足有限集合上的模型认证条件，且在其中对原意图改动最小（等距时取事件更早者）。

由有限集合上的字典序选择直接得到（距离与事件时刻都相同时，按候选网格的固定顺序取先者，所以映射是确定的）。

**准确性说明：**

- 原意图只按"是否触发事件"放行，不再套用关键性与燃料条件；
- 候选事件可以是直接进入下降，不一定经过入口规划；
- 关键性条件 t + τ̂ + P > L 是"机会稀缺"的时间代理，不是对后续所有可达状态的计算。

**何时真正改善结局：** 认证把一次本会错过的关键窗口变成一次入口，需要三点同时成立：

- (a) 被选候选的预测事件在真值中兑现；
- (b) 后续决策不把系统带离该窗口；
- (c) 原意图确实会错过这次关键窗口。

三点各自对应一种可能的失效：预测不兑现、后续偏离、过早介入。所以认证不保证"从不伤害"，实验报告净效应与翻转数。

**与"仅在执行时加认证"的区别：** 只在执行时加认证，训练时不用，相当于后处理滤波器。ECC 在训练中也用同一个 𝒞（第 5.4 节）。

## 5.4 训练–执行一致学习

**认证诱导的转移：** 记执行层的宏转移核为 P_ℰ，则

  P_𝒞(x′, r | x, a) = P_ℰ(x′, r | x, 𝒞(x, a))。

**训练与执行用同一个 𝒞：**

- 经验池存的是策略提出的 a，不是 𝒞(x, a)；
- 回报与后继来自认证之后的真实执行；
- 评价器学的是"提出 a 时系统真实会发生什么"。

**性质 E2（学习对象一致）：** 在完整状态 x 上，这样收集的数据是马尔可夫决策过程 (P_𝒞, r̃, γ_d) 的样本，所以价值学习的对象就是包含认证的协调系统在执行时的真实后果。

- 对照：若只在执行时加认证，训练优化的是 P_ℰ，执行的却是 P_𝒞，两者不一致；
- 这正是 RL–MPC 综述指出的后处理滤波器问题：训练时不可见的滤波器使策略无法闭环最优（Reiter 等 2026，第 8.3 节）。

**推论（认证等价）：** 同一完整状态下，若 𝒞(x, a₁) = 𝒞(x, a₂)，两个提议的实际执行与后果分布相同，在相同后续策略下价值相等。

- 在认证会替代的区域，策略不必自己学会精确选出被认证的意图；
- 因此，如果在执行时关掉认证，与认证一起训练的策略不一定比单独训练的策略强。开发期观察到"执行时关认证，在环训练的模型性能下降"，与此一致。

**执行层预测的用途：** 只用于认证动作，不生成任何长期价值目标，也不改动 SAC 的损失。

**部分可观与函数逼近：**

- Bellman 对象定义在完整状态 x 上；策略只读 o、评价器读 (o, z_E)，是该对象的非对称函数逼近；
- 采集为异步双进程、离策略回放；
- 不主张无偏性或收敛性。

## 5.5 一次决策的完整流程

1. 策略给出 a ~ π(· | o)（训练时采样，执行时取均值）；
2. 若模式为 S / H：对 𝔅 ∪ {a} 做 48 s 模式预测，得到 a^e = 𝒞(x, a)；
3. 按 a^e 走 RWG 执行链，直到宏步结束：
   - 阶段目标 → 阶段规划 → 远场跟踪 / 近场 MPC；
   - 每 2 s 入口判定 → 入口规划与重定时 → 下降 → MPC；
4. 训练时，经验池存 (o, z_E, a, r̃, o′, z_E′, d)，存的是提出的 a。

**伪代码：**

```
训练（每个采集进程）
  初始化 x，观测 o、执行反馈 z_E
  循环（每次高层决策）：
    a ~ π_θ(·|o)                               # 策略只读 o
    若模式 ∈ {S, H}：对 𝔅 ∪ {a} 做 48 s 模式预测，a^e ← 𝒞(x, a)；否则 a^e ← a
    经 RWG（意图 → 阶段目标 → 规划 / 跟踪 → 入口规划与重定时 → MPC）执行 a^e，
      直到宏步结束（16 s / 偏离提前结束 / 入口或下降后直到终局）
    r ← 真实回报；r̃ ← r + γ_d Φ(x′) − Φ(x)（终局 Φ(x′) = 0）
    存入 (o, z_E, a, r̃, o′, z_E′, d)                # 存提出的 a
    学习进程：每条转移 2 次 SAC 更新（第 06 节）
执行（测试）
  a ← π_θ 的均值；a^e ← 𝒞(x, a)；经同一执行链执行 a^e
```

**方法总图（建议只画一张）：**

- 左：策略 π(a | o)；
- 中：执行机会认证 𝒞，读 48 s 模式预测，输出 a^e；
- 右：RWG 执行链（扫掠锥意图 → 阶段规划 / 跟踪 → 入口规划与重定时 → 近场 MPC），作用于六自由度真值；
- 下方两条反馈：真实转移 (r̃, x′) 回到经验池；执行反馈 z_E 只进入评价器；
- 标注"训练与执行使用同一 𝒞"。

**参数依据：** 预测时域 48 s 即 3 个阶段，覆盖一次窗口；3 × 3 候选均匀覆盖动作盒。这两项只影响执行，可以做只评估的敏感性分析（放附录，正式实验未登记）。

## 5.6 不主张

- 安全保证或捕获保证（安全只由真值判定）；
- 认证对连续动作最优，或"从不伤害"；
- 重定时必然提高捕获率，或重定时后的到达必在同一次经过内；
- 非对称评价器无偏或收敛；
- 优于动作空间之外的直接入口规划（它只作参照）；
- 跨算法、跨任务的迁移性能。"与学习算法无关的协调接口"只作结构性描述。

**开发期试过、未纳入方法的做法：**

- 反事实价值标签；
- 动作梯度修正；
- 历史校准的机会图作为评价器输入；
- 动作层证书作为评价器输入；
- 带机会时刻承诺的最小干预调节器。

它们在开发期都没有带来改进，见 `docs/DEAD_ENDS.md` D39–D45，可作讨论或附录材料。

## 1. 诊断（沙箱实测）

脚本 `experiments/probe_v3_blend_stress.py`；产物 `eval/adp/v3_t0b_blend_stress.json`。

**方法**：目标系里的暂存方向 `h(t)` 只取决于目标翻滚和开局位置，与追踪器之后的动作无关。
所以对 12 个种子（263000–263011，不在任何评估块内）各记录一次完整 300 s 的 `h(t)`，
再在离线状态下，把训练式的任务状态序列回放给三种方向插值：
- 3 条常数 c（0.3 / 0.5 / 0.7）；
- 6 条随机游走（δρ ±0.5 m，δc +0.05 / −0.02，与 V3 动作上限一致）。

每条序列都施加与 env 相同的"同一时刻 0.40 m 度量上限"。

| 插值 | 失效位置 | 超过 3 m（108 条序列） | 逐步超出 2.4 边界的决策数 | 最坏 |
|---|---|---:|---:|---:|
| V2 最短弧 slerp | 暂存方向接近抓取方向的**反向**（148°–175°） | 39 | 469 | 18.0 m |
| T0 带记忆旋转轴 | 暂存方向**接近**抓取方向（3°–5°） | 26 | 185 | 31.7 m |
| **方向状态限速（本修复，0.40 m 预算拆分）** | —— | **0** | **0** | **2.95 m** |

T0 版本修好了反向点，却在另一端坏了。原因：
- 暂存方向接近抓取方向时，`h − d → 0`，旋转轴失去定义；
- 解卷绕后的角度可能已经累积到接近 2π，中间的 c 会把参考放到另一侧，并随轴一起翻转。

只有 `h` 曾靠近 `d` 到 5° 以内的 3 个种子（263000 / 263004 / 263005）出问题，这与训练中"部分回合、部分种子"出现大跳变的分布一致。

**结论：任何"只由 (h, d, c) 决定的方向公式"都会在某处不连续**。方向在单位球上从 h 到 d 的插值，没法在所有相对位置上都连续地定义。
所以不再找公式，改为**让施加的方向成为一个状态，限速跟随公式给出的目标**。

## 2. 修复规格

### 2.1 方向状态与每步更新

新增状态 `u`（单位向量，目标系），每回合 reset 时清空。每个 learned 决策（候选先经同一时刻 0.40 m 上限，确定新的任务状态 z 与半径 r'）：
```
g         = slerp_shortest(h, d, c)                        # 无状态目标方向：V2 最短弧即可
Δr        = |r' − r_prev|                                  # 本决策半径变化（第一个决策取 0）
max_ang   = 1.2 · |ω_target| · Δt  +  max(0, 0.40 − Δr) / r'   # 0.40 m 预算在"半径变化"和"额外转角"之间分配
若 u 为空：                     u ← g
否则 若 angle(u, g) ≤ max_ang： u ← g
否则：                           u ← 沿 u→g 的最短弧转过 max_ang
参考 = r' · u
```
- `|ω_target|` 用**当前目标角速度模长**，不用标称值：跨工况翻滚更快时，c = 0 的惯性保持仍能跟上；
- u 与 g 恰好反向时，转轴取确定性的正交方向（沿用 `_fallback_blend_axis`）；
- 跟上时 `u` 严格等于 `g`，所以 c = 0 → `u = h`，c = 1 → `u = d`。

**为什么要把 0.40 m 预算拆开**：上一版写的是 `max_ang = 1.2|ω|Δt + 0.40/r`，再加上半径变化，理论最坏值会超出验收上限 0.40 m（沙箱最坏 2.95 m 没超，是因为那组序列没同时走满两项）。
拆开之后，由三角不等式 `|r'u' − r u| ≤ |r' − r| + r'·angle(u, u')`，**上限可以证明**，不靠采样碰运气。

### 2.1b 方向状态进入观测（Markov）

`u` 是跨决策的状态，而且只在跟不上时才与 `g` 不同。策略看不到它，决策过程就不是 Markov 的。
- `task_state_v3` 观测**末尾追加 `u`（目标系，3 维，单位向量，不再归一化）**，维度 39 → 42；
- 旧 10k 模型只用于第 3 节第 7 项的压测：加一个**只读兼容适配器**，把 42 维观测截掉末尾 3 维后喂给旧模型。适配器只允许在压测脚本里使用，**不得进入训练或正式评估路径**；
- `v3b` 训练、M2 数据、V_L / V_B 的输入一律用 42 维观测。

### 2.2 与同一时刻度量上限的配合（重要）

`_limit_task_state` 的二分会多次调用参考函数评估**候选**状态。**这些评估不得更新 `u`**：
- 写一个纯函数 `_direction_step(u_prev, g, max_ang) -> u_new`；
- 候选评估一律用上一决策提交的 `u_prev`；
- 只在决策最终施加时提交一次 `u ← u_new`。

沙箱压测就是这样实现的（`ref(state, commit_state=False)`）。

### 2.3 去掉带记忆旋转轴

`_v3_memory_axis_direction` 及 `_v3_blend_axis` / `_v3_blend_angle` 删除（或保留代码但不再调用）。
T0 中基于它的测试改为针对新实现。

### 2.4 验收边界：逐步、按当前半径和转速计算

原来的"< 3 m"是固定数，没考虑半径和翻滚率。新的逐决策硬边界，与 2.1 的更新规则一致、可证明：
```
|r_{k+1} − r_k|（目标系） ≤ L_k = 0.40 m + 1.2 · |ω_target,k| · Δt · r_{k+1} + 1e-6
```
标称翻滚率下，25 m 处约 2.9 m，27.7 m 处约 3.2 m。下层建议的弦长形式 `0.40 + 2r·sin(|ω|Δt/2)`（|ω| 取 0.05）数值几乎一样；
这里取弧长形式、并用当前 |ω|，是为了和 2.1 的更新规则逐项对应，跨工况也成立。
262421 的 3.32 m 按这个边界、用那一步的实际半径和转速重判。

## 3. 测试（全部写成测试锁死）

1. **候选只读**：一次决策内 `_limit_task_state` 的二分会多次预览候选参考，`u` 在预览过程中逐位不变；
2. **每决策恰好提交一次**：给提交函数计数，一个 learned 决策计数恰为 1，baseline 决策为 0；
3. **合成几何**（秒级）：h 在单位球上匀速转动，分别以 3°、90°、177° 的最近距离掠过 d，另加正好穿过 d 和正好穿过 −d 的两条；
   c 取 0.3 / 0.5 / 0.7 常数，再加一条固定随机种子、同时走满 δρ 与 δc 的随机游走；每一步满足 2.4 的边界；
4. **端点**：c 恒为 1、跑到跟上后 `u == d`（差 < 1e-12），`z = (ρ_max, 1)` 的参考严格等于 `desired_position`；c 恒为 0 时 `u == h`；
5. **观测**：`task_state_v3` 观测为 42 维，末 3 维等于 `u`；维度守卫拒绝 39 维模型直接加载（只有压测适配器能用）；
6. **baseline 逐位等价**：全程 baseline 的逐控制步 wrench 与 Pure MPC 相等（12 回合）仍然成立；
7. **真实条件压测**（验收，分钟级，可并行）：
   - 三个 10k checkpoint 各跑 12 个回合（种子 263000–263011），**随机策略**（与训练同口径），通过只读适配器，**跑满 300 s**（除非回合自然结束）；
   - 用 T0.3 的 `reference_jump_target_m` 逐决策按 2.4 的边界检查：**违例必须为 0**；
   - 同时要求：无 NaN，QP 无解与零推力回退次数不多于 V2 评估的水平；
   - 报每个种子的违例数、最大跳变、p99、最大 `angle(u, g)`（衡量滞后程度）；
8. 原有全套测试仍绿。

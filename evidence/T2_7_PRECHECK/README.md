# T2_7_PRECHECK：T2.6W1 之后的上层诊断与 T2.7 的依据（沙箱，探索性）

**性质：** 上层沙箱的只读诊断（2026-10-30 至 10-31），不训练、不进论文主表。行为策略多为固定规则，样本量小，数字只作探索性证据，用来决定下一处改动对象。冻结代码：诊断时为科学 `e2d4c14` / `91b346b`（环境 0.4.3）。开局：审计段 2,910,000+（`输入/CAL.json` 为 `t2_audit warmup` 的共享校准）；个别对比用开发块 294000–294047（已反复使用，只作开发验证）。任务：紧急截止 U(140, 200) s，预算 3.0 m/s（除第 5 项）。

## 1. T2.6W1 回报为什么分化（证据内计算，见 HANDOFF 讨论）

| 训练 | 四点平均回报 | 紧急捕获合计 |
|---|---|---|
| SAC 种子 0 / 1（T2.6W） | 36.2 / 19.3 | 78 / 66 |
| EACC 修复后 种子 0 / 1（T2.6W1） | 27.9 / 39.0 | 71 / 81 |

同一 SAC 的两个种子相差约 17 分；按 4 条训练估计，跨训练标准差约 10 分。25 个紧急开局中 10 个所有训练都捕获、4 个都不捕获（294003、294017、294026、294038），全部差异集中在 11 个有争议的开局上。

## 2. 标签视界（`脚本/horizon_probe.py`，`记录/horizon/`，`记录/horizon_SUMMARY.txt`）

19 个紧急回合、52 个离截止 40–140 s 的决策、416 个候选，模型逐段外推 1–4 段与真值（保持意图续飞）比较：关键候选对判对 21（16 s）→ 34（32 s）→ 34（48 s）→ 34（64 s），判错始终为 0；预测位置误差中位 0 / 0.20 / 0.68 / 1.23 m。延长视界不增加排序信息。

## 3. 直接下降路线（`脚本/route_probe.py`、`脚本/descent_check.py`，`记录/capture_route*`、`记录/descent_trigger.json`）

4 个固定策略 × 40 个开局的 135 次成功中，3 次不经入口规划直接下降；在模型 32 s 可靠视界内补下降判据，触发 11 次中 2 次真捕获、0 个直接捕获。不作为改动对象。

## 4. 执行器捕获机会（`脚本/opportunity_probe.py`、`脚本/early_probe.py`，`记录/opportunity_*`）

- 离截止 40–140 s：执行器直连规划可行的候选 39/416，飞到底 27/39 捕获；候选间可行性不同的决策只有 2/52。
- 开局前 3 个决策（5 个回合部分完成）：超时回合 2910001、2910008、2910012 在 t = 0 时，执行器从每个候选的阶段末都能规划出捕获（8/8、6/8、8/8），而"保持意图"续飞 0/8；机会对所有候选同时存在、同时消失。

## 5. 推进剂分配（未采用；`脚本/budget_probe.py`，`记录/budget_not_adopted*`）

分配 U(1.2, 3.0) m/s（下限取 G★ 成功捕获 Δv 中位 1.24，与 EACC 结果无关）下，燃料消耗多的 c_10_5 只有 2/25 回合耗尽，满足审计条件的决策 6 个，真值不区分候选。要让燃料成为决定因素须把分配压低，即逐档挑点（T2.6B 的撤回理由），不采用。代码未提交。

## 6. 动作空间内能否实现执行器的捕获（`脚本/track_probe.py`、`脚本/track_dev.py`，`记录/track_*`）

"跟踪执行器规划"规则：每个阶段决策求一次直连 G★ 规划（不提交），选阶段目标最接近规划 16 s 后状态的阶段意图（9 × 9 网格），完全在二维阶段动作空间内。

| 19 个紧急审计开局 | 捕获 | 平均回报 |
|---|---|---|
| 跟踪执行器规划 | 19/19 | 77.0 |
| 直连 G★（动作空间外） | 18/19 | 67.1 |
| 规则 rally | 9/19 | −30.7 |

开发块 48 个开局：跟踪规则 38.9、43/48（紧急 20/25），与收敛的 SAC 种子 0 持平；相对 SAC 种子 1 的配对差在 1000 / 2000 / 4000 步为 +33.8 / +21.1 / +12.7，相对修复后 EACC 种子 0 为 +23.6 / +11.1 / +4.5（`记录/track_development_SUMMARY.txt`）。

## 7. 被否决的设计：执行器机会下界（`记录/bound_design_rejected.patch`，`脚本/bound_audit.py`，`记录/bound_design_rejected*`）

设计：对每个候选，用执行器在预测阶段末的规划可行性给出单边下界 Q(s, a) ≥ r₁ + γĜ − Φ(s)。训练前真值审计（2 个紧急回合部分完成后停止）：带下界的动作 19 个，"先执行该动作、再跟踪规划"续飞的真值只捕获 2 个；下界相对真值中位 +190，89% 乐观超过 50。原因：直连规划可行 ≠ 阶段动作空间内可实现——偏离计划一段后跟踪救不回来（2910001：t = 0 的跟踪候选下界 74.7、真值 78.7 捕获；t = 16 s 同一候选下界 75.1、真值超时）。设计未提交，不训练。

## 8. 采用的设计：执行器引导（科学 T2.7 提交，`记录/guide_smoke_*`）

训练时，采集进程以概率 0.5·max(0, 1 − t/2000) 执行执行器的跟踪意图代替策略动作，replay 存实际执行的动作（离策略 SAC 的合法数据，不涉及模型乐观偏差）；评估只用确定性策略。沙箱冒烟：40 步中 12 步被引导，manifest 记录 `guide`、`guide_p0`、`guide_until`。

## 9. 开训前技术复核（研究层 10-31 要求；`脚本/mix_probe.py`，`记录/mix_review*`，冻结代码 `2208a51`）

每个阶段决策以概率 p 执行执行器投影意图，否则执行基础动作；24 个审计开局（紧急 10、经济 14）：

| 配置 | 紧急捕获 / 回报 | 经济捕获 / Δv |
|---|---|---|
| 随机，p = 0 | 3/10，−70.8 | 10/14，1.86 |
| 随机 + 引导，p = 0.5 | 9/10，54.6 | 14/14，1.45 |
| 随机 + 引导，p = 0.25 | 5/10，−28.7 | 13/14，1.73 |
| rally，p = 0 | 6/10，−4.4 | 14/14，1.40 |
| rally + 引导，p = 0.5 | 7/10，16.0 | 14/14，1.50 |

- 混合执行不破坏捕获过程，所有配置无 unsafe。
- 经济任务燃料：rally 之上加引导多用 0.10 m/s（回报 −3.8）；开发块上跟踪规则相对收敛训练多用 0.03–0.07 m/s，经济 23/23 捕获。无明显燃料退化。
- 投影与执行：119 次引导中阶段规划全部可解，保持 1 次；实际执行与阶段目标偏差为 0；53% 的请求超过单段速度增量上限而被截到上限，实际 16 s 状态与执行器规划相差中位 0.69 m（P90 1.30 m）——投影的固有近似，不影响引导效果。
- 结论：未发现确定的设计缺陷，冻结方案不变。

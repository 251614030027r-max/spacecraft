### 1.1 主图：靶星体系下的三条轨迹 + 旋转走廊

参照 `References/哈工大.pdf` 的轨迹图形式（只借图的形式，不借它的建模贡献）。

## 2. 两种失败模式的物理机制（都已在任务里，不是造出来的）

### 2.1 外围发散 —— 机制已存在，但被一条人为栏杆挡住了

在半径 `r` 上以角速率 `ω'` 共旋，需要向心力 `m ω'² r`。单轴 5 N 能撑住的上限：

| r (m) | 可持续 ω' (rad/s) | 可持续切向速度 (m/s) | 靶星速率 0.0412 下的共旋推力 |
|---|---|---|---|
| 30 | 0.0397 | 1.190 | 5.41 N（**已超单轴**） |
| 20 | 0.0486 | 0.971 | 3.60 N |
| 16 | 0.0543 | 0.869 | 2.88 N |
| 12 | 0.0627 | 0.752 | 2.16 N |
| 8 | 0.0768 | 0.614 | 1.44 N |
| 6 | 0.0887 | 0.532 | 1.08 N |

指令角速率一旦超过这条线，净外向加速度 `ω'²r − 5/m` 立刻把飞行器甩出去：

```
从 16 m 甩到 30 m 距离失败:  ω'=0.060 -> 51.8 s   ω'=0.070 -> 29.9 s
                            ω'=0.080 -> 22.5 s   ω'=0.100 -> 15.8 s
```

**这是内生的、动作相关的失败，完全符合诚实红线。**

**问题在于现行的 `outer_inertial_speed_limit_m_s = 1.20` 恰好压在推力能力线上**
（16 m 处推力只撑得住 0.869 m/s 切向，30 m 处 1.190 m/s）。
于是任何超出推力能力的机动会**先撞限速**，被记成"限速违约"，
**"飞出去"这条曲线永远画不出来。** 见 §3 的 M3。

### 2.2 接近失败 —— 锥面几何 + 窗口不等

靶星自由翻滚，角动量 `H = I ω` 惯性守恒，所以体固定接近轴在惯性空间
**扫过一个以 H 为轴、半角 β 的锥**。追踪器必须把自己的方向送上那个锥才可能对准，
否则等多久都对不上。

实测（seed block 262000，追踪器保持复位方向）：

```
seed 262000  β=75.7°  追踪器距 H 138.9°  窗口 t=139s:28.9°  t=291s:20.9°   <- 第二窗口更好
seed 262001  β=75.7°  追踪器距 H 136.3°  窗口 t= 37s:30.6°  t=189s:23.9°   <- 第二窗口更好
seed 262002  β=75.7°  追踪器距 H  47.7°  窗口 t=  0s:56.7°  t=152s:63.0°   <- 第一窗口更好
seed 262003  β=75.7°  追踪器距 H 155.6°  窗口 t=151s:45.0°                 <- 300 s 内只有一个窗口
seed 262004  β=75.7°  追踪器距 H  52.3°  窗口 t=132s:57.4°  t=284s:65.2°   <- 第一窗口更好
```

**"选这个窗口还是下一个"是真决策**，跨度 150–290 s，而 h20 的视界是 2 s、h50 是 5 s。

### 2.3 为什么"慢悠悠接近"不再总是可行

把方向转过角度 `θ`，在半径 `r` 上受推力约束：`T = θ√(r/a)`、`Δv = θ√(a·r)`，`a = 5/106`。

| θ | 在 16 m 做 | 在 10 m 做 | 在 6 m 做 |
|---|---|---|---|
| 60° | 19.3 s / 0.91 m/s | 15.2 s / 0.72 | 11.8 s / 0.56 |
| 90° | 28.9 s / 1.36 | 22.9 s / 1.08 | 17.7 s / 0.84 |
| 120° | 38.6 s / 1.82 | 30.5 s / 1.44 | 23.6 s / 1.11 |
| 156° | 50.1 s / 2.37 | 39.6 s / 1.87 | 30.7 s / 1.45 |

**在 6 m 做比在 16 m 做省 39% 的 Δv 和 39% 的时间。**
当前整条任务 Δv 约 1.8–2.2 m/s，所以在 16 m 处做一次 156° 的重定位（2.37 m/s）**直接让成本翻倍**。

"慢悠悠"策略 = 在外面转 + 等相位 + 接近：

```
θ=90°   28.9 + 152.4 + 110 = 291 s   放得下
θ=120°  38.6 + 152.4 + 110 = 301 s   **超时**
θ=156°  50.1 + 152.4 + 110 = 313 s   **超时**
```

**所以在需要大角度重定位的 episode 上，"慢悠悠"会超时，必须先下降再重定位。**
这正是那个值得学的决策，也正是短视界 MPC 拿不到的东西。

**前提是 β 不能是常数。** 当前 `TARGET_BASE_TUMBLE_RAD_S` 方向写死，五个 seed 的 β 全是 75.7°，
一条针对 75.7° 调好的固定规则可以吃掉全部 seed。见 §3 的 M2。

## 3. 任务定义：M1 + M2 + M3，一个 commit

三项都是任务几何/边界的**定义**，分轮改会让前一轮结论在后一轮之后作废。
归因通过**评估配置**保住（每项都做成可开关的配置字段），不通过拆 commit 保住。

### M1 — 走廊入口截面语义（替换 6 m 球面闩锁）

**要改掉的**：`terminal_activation_range_m = 6.0`，一个隐形球面，从任意方向碰到即全套终端约束
生效，越界当场判死。实测越过时必须落在旋转接近轴的 **26.8°** 锥内（随机撞上概率 5.4%）；
失败 seed 的离轴角是 27.6° / 34.9° / 38.0°，失败前 1–2 s 推力打满 8.66 N。
这是一道看不见的悬崖，写进论文会被直接质疑。

**改为**：

```
entry_port_axial_distance_m = 4.5                  # 沿接近轴自 port 起算，轴线上等价中心 6 m
entry_disc_radius_m         = 4.5 * tan(35°) = 3.15
```

- 终端走廊 = 从 desired 位姿到入口截面的**截断锥**；锥与入口盘都定义在**靶星体系**，随翻滚旋转。
- **闩锁 = 合法穿越入口盘**：轴向距离由外向内穿过 4.5 m 的那一步，且
  (a) 横向距离 < 3.15 m，(b) 目标系总速 ≤ 0.35 m/s，(c) 闭合速度满足既有随距离律。
- **单向闩锁**：锁存后短暂退出不解除。
- **非法穿越 = 不锁存、继续飞、不判违约**，只累加诊断计数 `illegal_terminal_entry`。
  **这条是 M1 的成败关键**：判死等于把球面悬崖换成圆盘悬崖，白改。
  非法穿越之后飞行器仍在外区，可以退出去重新组织下一次进入 —— 那正是"接近失败"的诚实形态。
- 全程有效：keep-out 2 m、FOV 50°。闩锁前有效：径向刹车包络。
- 完成判据不变，且**必须先锁存**。

### M2 — 靶星翻滚方向按 episode 采样（让 β 不再是常数）

`target_initial_state(tumble_scale=0.20, phase_seed=<episode seed>)`，
**幅值锁死 0.041231 rad/s，只采样方向**。`_cached_target_trajectory` 的缓存键已含 `phase_seed`。

实测 12 次抽样的 β：**14.6 / 34.1 / 39.7 / 45.5 / 62.1 / 64.0 / 66.1 / 76.7 / 77.9 / 103.1 / 117.2 / 156.4 度**。
入口几何每个 episode 都不同，固定规则无法针对某一个 β 调参。

代价已核验，两条硬要求都满足：
- 共旋**力矩** `I_c ω̇ + ω × I_c ω` 最大 **0.0048 N·m = 0.6 N·m 的 1%**；
- 共旋**推力** `m ω² r`：16 m 2.88 N（58%）、6 m 1.08 N（22%），**不持续饱和**；
- 幅值不变，与 `References/北航.pdf`（0.0173 rad/s）的转速对比基准不受影响。

> **不要用 `CLAUDE.md` trap 9 否定 M2。** trap 9 记录的是 `single_phase_phase_sampled` 探针在
> **旧 S1-v2 任务**上采样相位为负。旧任务从 10–14 m 起步、已经共旋、有走廊制导，
> 锥面几何从不起作用。本任务从 15–20 m 起步、无共旋初始化、无中间参考，锥面几何是主导。
> 报告时必须写明这个区别。

### M3 — 让"飞出去"成为可见的失败（拆掉挡住它的栏杆）

```
outer_inertial_speed_limit_m_s : 1.20  ->  2.00
```

理由（§2.1）：1.20 恰好压在推力能力线上，任何超出推力能力的机动会先撞限速，
于是"飞出去"被记成限速违约，主图里那条发散曲线永远画不出来。
**外区的物理边界应当是推力能力 + 30 m 距离失败，而不是一条人为速度栏杆。**

保留不动：
- **径向刹车包络** `sqrt(2·0.020·(r−2))` —— 它是物理自洽的可恢复性约束，只限**向内**径向速度；
- `max_distance_m = 30`；keep-out 2 m；FOV 50°。

`2.00` 只作为防止数值发散的理智上限，不应成为约束的绑定项；
若正式批次显示它仍在绑定，报上来，不要自行再调。

### M4 — 明确不改的东西

| 项 | 值 | 理由 |
|---|---|---|
| 靶星转速幅值 | 0.041231 rad/s | 提高转速只缩短周期、让窗口来得更勤（更容易），并让终端向心力按 ω² 涨到饱和；且文献对比基准 |
| episode 上限 | 300 s | 必须容下 1–2 个窗口，这正是"这个还是下一个"的载体；§2.3 的超时分界也建立在它上面 |
| 推力 / 力矩 | ±5 N / ±0.6 N·m 每轴 | 已核验不饱和（58% / 1%） |
| 起始距离 | 15–20 m | 不变 |
| 完成判据 | 0.25 m / 10° / 0.05 m/s / 0.02 rad/s，保持 1 s | 不变 |
| 奖励结构 | 不大改 | 审查稿 §13 |

## 4. Oracle 的返修与定性（独立 commit，在 M1–M3 之前）

**定性必须改。** 本任务 `phase2_target_model_mismatch = 0.0`，缓存轨迹就是标称模型从 t=0 的
确定性外推，**"可访问 future truth" 站不住**。正确说法：**一条常数由人手定的开环计划**。
它的 coast 搜索目标是 `initial_direction · match_entry_direction`，
**在最小化转向燃料，不是在选进入时机** —— 不得称它演示了时机决策。禁称 optimal oracle。
它唯一的职责是：**证明存在一条又便宜又安全的路径**，因此找不到的控制器是规划有问题。

必做返修：

1. **解耦时间常数**：新增 `OUTER_DESCENT_TIME_S`，半径在这个固定且可行的时长内滑到
   `OUTER_STAGING_RADIUS_M`，**然后保持**，直到 match 开始。
   当前实现把半径下滑摊在整个 coast 上，缩短 coast 会自动加快径向平移。
   **实测警告：直接把 `COAST_MIN_TIME_S` 降到 20 会让 seed 262001 的计划需要
   0.246 m/s² = 单轴能力的 5.2 倍，并且计划本身就越过刹车包络 0.197 m/s；
   seed 262002 会得到 `match_start = −20 s` 的非法计划（因为 `COAST_MIN < MATCH_TIME`）。
   不要直接改这两个常数。**
2. **搜索窗口**下限 ≥ `OUTER_DESCENT_TIME_S + MATCH_TIME_S`，上限至少覆盖一个自转周期
   （当前 `[90,170]` 有 3/5 的 seed 撞在边界上）。
3. **返修后做一维扫描**（不是单点）：在 `coast_min × descent_time` 网格上求
   "仍 5/5 零违约、最差归一化裕度 ≥ +0.14"的最短总时间。这个数只作参考，**不作性能分母**。

**已作废：** "oracle 217.7 s vs h50 65.0 s = 3.3 倍安全代价"。
实测 match 段恒 40.0 s、cross+terminal 恒 69.5 s，只有 coast 变，109.5 s 与安全无关。
任何以 oracle 时间为分母的百分比一并作废。

## 5. 验收（最小语义验证，不扩散）

M1：
1. 从入口盘外侧不同方位经过中心 6 m 球面 → **不触发**终端约束；
2. 盘内合法穿越（横向 < 3.15 m 且速度条件满足）→ 锁存；
3. 横向超盘的穿越 → `illegal_terminal_entry` +1，**不锁存、不违约、episode 继续**；
4. 锁存后退回 4.5 m 外 → 仍锁存；
5. keep-out / FOV / 径向刹车包络的既有真值检查逐条不变；
6. 完成必须在锁存之后。

M2：
7. `phase_seed` 相同 → 靶星轨迹逐位一致；不同 → β 不同且 `|ω|` 恒为 0.041231；
8. `phase_seed=None` → 与本次修改前逐位一致。

M3：
9. 构造一个在 16 m 处指令 ω'=0.08 的诊断 episode → 应在约 22 s 内以
   **`distance_failure`** 终止，而不是限速违约。这条同时是主图曲线 A 的素材。

Oracle：
10. 返修 + M1–M3 之后，**≥8 个 seed** 重跑，仍需 5/5 完成、零真值违约、推力通道饱和步数 0%。

`python -B -m pytest -q` 全绿（基线 168 passed）。

## 6. 四行基线与冻结规则

| 行 | 冻结要求 |
|---|---|
| Pure MPC h20 | `terminal_weight` 冻结在当前公平值，不再随结果上调 |
| Pure MPC h50 | 同上；算力只报**串行单进程**的 p95/max |
| **Hand-guidance + MPC** | 参数**只在开发 seed 上定一次然后冻结**；这是唯一真正的对照组 |
| SAC-guided MPC | 训练闭环内耦合；≥3 训练种子报分布 |

**Hand-guidance 必须从 oracle 的结构派生**（外区接近 → 锥面重定位 → 合法穿越），
只把窗口选择改成在线可算，不要另起炉灶重写一条。
理由不只是防稻草人：只有同结构，它与 oracle 的差值才等于"离线搜索 vs 在线规则"这一项。

允许它用：当前可观测状态、靶星姿态与角速度、自由刚体外推（无失配，合法）。
禁止它用：缓存的未来真值轨迹、逐 seed 调参、离线 per-episode 优化。

**性能阈值（审查稿 §12 的 10% 量级）的分母是这一行，不是 oracle。**

SAC 的动作接口保持已声明的形式：**靶星中心、惯性定向坐标系下的 3D 航点，保持 2 s**，
经 `reference_source="external_local"` 进 QP。该接口的帧定义已于 2026-09-04 修正，不再改。

## 7. 执行顺序（施工，不是门禁）

```
S1  Oracle 返修 + 定性改写 + 一维扫描                  -> 独立 commit
S2  M1 + M2 + M3 一个 commit + §5 全部验收             -> 独立 commit
S3  新几何上重跑 Pure MPC h20 / h50，5 seed 探路
    并采集主图曲线 A 的素材（含一条发散轨迹）
S4  实现并冻结 Hand-guidance + MPC，5 seed             -> 主图曲线 B
S5  external_local 接口检查：对高层航点序列做离线优化
    （2–3 段航点 + 1–2 个切换时刻，闭环跑；不要回放 oracle 轨迹）
S6  进入 SAC-MPC 训练                                  -> 主图曲线 C
```

**唯二的真停止点**（其余一律照做并如实报，不作为判死条件）：

1. **§5 第 10 条不过** —— M2 放大了几何离散度，若 oracle 在 ≥8 seed 上不能 5/5，
   说明任务本身不可解，必须停下报告，不要往下走。
2. **S5 表明接口传不出指令** —— 若允许大量离线计算仍无法通过 `external_local`
   明显改善成功率/时间/效率，则先改接口再训练。这不是立意问题，是工程前提：
   接口不通，训练会空转。

其余情形一律继续。**即使 Hand-guidance + MPC 表现很好，也继续做 SAC 那一行** ——
那种情况下论文的结论形状变成"学习层把固定规则的保守性拿掉了"，仍然成立，
只是提升幅度要如实报。

S3/S4/S5 一律 5 seed 探路，**正式上报 20 episodes**。

## 8. 回报格式

```
commit / manifest
任务几何与本次唯一改动
seed block / episode 数
方法与冻结参数
completion rate / completion time
force impulse 或等价 Δv
worst truth margin（RK45 真值 + 真实几何判定）
controller 串行单进程 p95 / max
失败模式分列：distance_failure / illegal_terminal_entry / timeout /
             corridor / speed —— 五项分开计，不得合并
本步判定：PASS / FAIL / INCONCLUSIVE
```

## 9. 红线（不因"放松管理"而失效）

- **≥3 seed 才下判断**；n=1 结论上一轮连翻三次。正式数字 20 episodes。

## 10. 已作废，不得再引用

- "oracle 217.7 s 对 h50 65.0 s = 3.3 倍安全代价"，及任何以 oracle 时间为分母的百分比；

- "没有实时视界能完成"、"单一权重不能同时安全且收敛"、"燃料 1.60 倍"；
- `logs/precapture_planning_baseline/*.json` 全部（错误转速）；
- 称 oracle 为 optimal oracle，或称它"可访问 future truth"；
- **"提高靶星转速可以增加规划难度"** —— 周期 `2π/ω` 缩短会让窗口来得更勤，反而更容易；
  提高转速只增加执行负担（终端向心力按 ω²），实测 0.0825 rad/s 时 8 m 处即需 5.77 N > 5 N；
- **"收紧外区速度上限可以造出追/等决策"** —— 实测在 0.35–1.20 m/s、150–300 s 的全部组合里，
  "等"在 12 个相位中赢 12 个（唯一例外是 150 s 的一个相位）。追的向心代价按 `ω'²` 涨，等按
  `(ω−Δ)²` 降，追永远更贵。

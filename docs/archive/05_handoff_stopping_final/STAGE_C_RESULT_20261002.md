## 判定之后的诊断（探索性，不作结论）

脚本：`experiments/v3_stage_c_diagnostics.py`。

1. **标签没有问题**：没有"完成了但有违规"的交接状态，即标签没有被学习策略前缀里的违规污染。B1 中相邻两个决策的标签翻转率为 6.1%，说明可接管区域的边界清晰但相当破碎。
2. **问题集中在开局**：在 τ = 0.95 下，144 条轨迹中有 111 条的第一次触发发生在 k = 0，规则退化成了"多数开局直接用 Pure MPC"。而在 k = 0，判断器分不出哪些开局 Pure 能完成，折外 AUC 只有 **0.45**。这里只有 **48 个独立开局**，其中 Pure 失败的只有 11 个；同一开局在三个模型下的 k = 0 观测完全相同。
3. **开局之后也不够**：只看 k ≥ 1 的状态，折外 AUC 为 0.79，加权精度最高约 0.90。按"开局先由学习策略飞、之后第一次触发就交接"在失败轨迹上模拟，31 条里救回 11–14 条，提前交接导致失败 15–17 条。
4. **固定时刻交接也不行**：在 262000 块上精确计算"学习策略先飞 T 个决策再交给 Pure"，T = 0, 10, …, 100：最好是 T = 20 时的 40/40/36，不比学习策略单独跑（42/33/38）好。价值全在按状态选择时机。

## 结论边界

- 可以说：用"当前状态 → 现在交接是否安全"的判断器，配合第一次触发即交接的规则，在这批数据上**达不到**预注册的可靠性要求；固定时刻交接也拿不到收益。
- 不能说："交接协调无效"（上界仍是 48/48 对 37/48）；也不能说"开局时 Pure 的成败在物理上不可预测"（48 个开局、11 个负例，样本太少，不足以下这个结论）。
- 按约定：不加风险判断器、安全集等模块，不用 D 来掩盖。下一步由用户决定。

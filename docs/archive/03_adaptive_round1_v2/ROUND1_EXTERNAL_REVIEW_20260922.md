## 1. 已测且我认为可靠的结论

全部真值 RK45 裁决、串行单进程、每个数字指向仓库内 artifact（SHA-256 见
`ADAPTIVE_ROUND1_CLOSEOUT_20260921.md` 第 14 节）。

### 1.1 接口有一个结构性缺陷（代数 + 测量双重确认）

- `a_commit = clip(1 + 2r)`：**21 个等距 commit 残差只产生 11 个不同参考点**，
  `r ∈ {0.0 … 1.0}` 这 11 个全部落在捕获位姿（= Pure MPC）上。
- 棘轮 `blend = max(历史, 本次)`：`blend` 到 1 后直接 return 捕获位姿，
  **一次门回退之后 2D 动作网格 15 个点 → 1 个参考点，动作空间 100% 惰性**。
- 三个 strict xfail 测试钉住（`tests/test_coupling_diagnostics.py` T-A/T-B/T-C）。

### 1.2 策略的第 0 步动作饱和在死半边（P0，三模型 × 48 种子）

| 模型 | 第 0 步残差中位 | 残差范围 | 想暂存 | 暂存存活到执行 |
|---|---:|---|---:|---:|
| 262410 | +0.9714 | [−0.3190, +0.9998] | 1/48 | 1/48 |
| 262411 | +0.9546 | [−0.1139, +0.9999] | 1/48 | 1/48 |
| 262412 | +0.9902 | **[+0.3796, +0.9997]** | **0/48** | 0/48 |

262412 在 48 个种子上残差最小值 +0.3796——**任何状态下都没有能力在第 0 步暂存**。
探针所依赖的代数已改为由环境测量交叉验证，**144/144 通过**。

### 1.3 门是次要成因（两组独立样本一致）

D1（下层，8 种子 × 3 模型）：gate fallback **6/24**、policy **18/24**。
P0（上层，48 种子 × 3 模型）：第 0 步门回退 16/8/9 of 48，均值 **23%**。
**两组独立样本给出同一个约 25/75 的分割。**

### 1.4 能力是训练期崩塌的，不是从未探索到（D0b）

| checkpoint | latch = 0 | 有效参考改变 | 完成 |
|---|---:|---:|---:|

| **60k ×3** | **12/12** | **0%** | 8/12 ×3 |

暂存早期可达且被大量使用，到 60k 精确归零；**262410 的 5k checkpoint 完成 11/12，
比训练完的 8/12 更好**（12 种子、随机滚动、单次采样——强提示，不是结论）。

### 1.5 收益/破坏账本（D4 + D4c，48 种子块）

|---|---:|---:|

### 1.6 工况级交叉被测否（D3）

| 策略 | 1.18°/s | 2.36°/s | 3.54°/s |

### 1.7 棘轮的继承理由不成立，但棘轮不能删（①）

| 棘轮 | 完成 | 平均 Δv | 平均存活 | 失败模式 |

## 2. 根因判定

| 代号 | 裁决 | 依据 |
|---|---|---|
| R1 门语义 | **次要，约 23–25%** | 1.3 |
| R2 探索不可达 | **证伪** | 1.4 |
| R3 表达不了 | **证伪** | `r=−0.265` → blend 0.735 → 7.42 m（离线证书的暂存点）；脚本臂 26.8% 介入 |
| R4 任务没决策 | **证伪** | 1.5，+4/48 真值零违约 |
| **R5 死半边 + 棘轮** | **成立，唯一主因** | 1.1 + 1.2 + 1.4 |

**终判**：`r ≥ 0` 占动作空间 50% 且**梯度恒为零**（参考在那里是常数），构成策略空间中的

单调推入该平台，暂存能力从 5k 的 4–6% 崩塌到 60k 的 0%。任务本身有 +4/48 的可得收益，
**接口使其不可学**。

## 3. 明确**不**成立的说法（审查请核对我们没有越线）

- ❌ **"耦合方法无效"**。它没生效（有效介入 0.1–0.5%），有效性**未知**。
- ❌ **"已验证基线保持"**。retained 36 / rescued 0 / destroyed 0 是**靠不作为**得到的；
  "残差 0 逐位等于 Pure MPC"本来就有单测钉着。**那是恒等式，不是实验结果。**
- ❌ **"随翻滚加快，暂存的燃耗优势出现"**（工况级交叉）。见 1.6，测否。
- ❌ **"棘轮可以删"**。见 1.7。
- ❌ **"40/48 是一行结果"**。它是**预言机上界**，要求门控完全正确。
- ⚠️ **D0b 的 11/12 vs 8/12 不是结论**（12 种子、随机、单次采样）。
- ⚠️ **D3 只比了两个固定策略**，所以它否的是工况级交叉，**没有否**"按状态选、
  而正确答案随翻滚率移动"——后者由 D5 测。

## 4. 我们自己犯的错（这一节最该被审查）

1. **协议 v1 有误判缺陷**。它记录了"训练时没有门"，但判据仍会把"探索不可达"读成
   "表达不够"。若按 v1 执行，会去重构动作空间——而真因是平台吸收。已在 v2 修正。
2. **预注册的 D1 归因预测错了**。预测"门回退占绝大多数"，实测 25%。
3. **预注册的 0.1–0.5% 介入率用 8 种子子块去验，注定读到 0**。那个率由 1–2 个
   episode 独家贡献（262040、262039），都不在 262000–262007 里。这是**预注册不精确**，
   不是机理理解有误——但它一度让下层按协议停下自主诊断。
4. **上下层重复劳动**。上层独立实现了 C1/C2/C3 和三个 xfail 测试，下层同时也做了，
   最后丢弃上层那 3 个代码提交（下层实现更好：给随机策略播了种，保证可复现）。
5. **D3 第一次运行跨了两个代码版本**（我在运行中 reset 了分支），已作废重跑。
6. **一处工具在整轮诊断中都是坏的**：`replay_hybrid_policy.py` 缺
   `--adaptive-task` / `--baseline-anchored-residual`，**根本加载不了这批 38D 模型**。
   逐决策诊断工具对主线模型失效，直到这一轮才修。

## 6. 唯一的设计结论（F2 与 F3 合并）

① 的结果把修复方向定了：**不是删棘轮，也不是原样保留**。

> **把 `blend` 拆开。** 它现在同时承载两件事——「接近距离」和「对旋转位姿的承诺」。
> 从 15–28 m 出发，策略无法表达"再靠近一点，但先别承诺那个旋转位姿"，只能把 blend
> 推到 1。修复是把这两件事分成两个通道，**单调性只作用在"位姿承诺"那一根上**，
> 距离通道保持可升可降。

配套（按优先级）：

| | 内容 | 验收判据 |
|---|---|---|
| **F2+F3（合并）** | 拆轴 + 单调性只作用于承诺轴 | **T-A**：每个有效动作区间都必须产生可观测的参考变化；且 ① 的无棘轮抖动不得回来（Δv 不得翻倍） |
| **F1** | 安全回退不得写不可逆模式状态 | **T-B** |
| **F4** | 门对"映射后参考/模式转移"去重，报告 effective-reference deviation | 门的介入率必须等于有效参考改变率 |

## 1. F1（★最高优先）恢复 MPC 的入口前瞻

### 问题

`513b715` 把 terminal 激活条件从「已锁存**或预测距离进入 6 m**」改为「**仅合法锁存**」。
后果：**闩锁之前，MPC 在优化里完全看不到入口盘的闭合速度限、总速限和走廊锥。**

Q1 的数据就是证据 —— h50 三次超时的非法原因都是"闭合过快"，而且瞄得很准：

```
262000  离轴 7.98°   闭合 0.276  限 0.20
262002  离轴 10.69°  闭合 0.266  限 0.20
262004  离轴 13.37°  闭合 0.259  限 0.20
```

**它对得上门，就是刹不住 —— 因为没人告诉它门口有限速。** 超约 30%。

这等于给控制器一个它看不见的约束再说它做不好，与审查稿 §1「不得为制造 gap 而削弱 Pure MPC」直接冲突。
**S3 与 S4 现有的全部 MPC 侧数字因此作废。**

### 修法

- **真值侧不动**：仍然只有合法 outside→inside 穿越才锁存。
- **MPC 侧恢复逐视界索引的前瞻**：对每个名义视界状态，若其**预测**的轴向位置会穿到入口面以内
  （即预测 port-axial 距离 < `entry_port_axial_distance_m`），就为该索引激活 terminal 行
  ——走廊锥面、目标系总速、随距离的闭合速度律。
  这正是 `docs/PRECAPTURE_TASK_SPEC.md` 原 MPC contract 描述的语义，只是把 6 m 球面换成入口面。
- 固定行数与激活/失活的写法不变，只改激活条件。

### 验证（够用即可）

重跑 h50 的 262000 / 262002 / 262004 三个 seed，检查**穿越入口面时刻的闭合速度**：
- 若降到 ≤ 0.20 m/s → F1 成立，继续；
- 若仍超限 → 报上来，不要自己继续改。

## 2. F2 查清「非法穿越之后能不能退出去重进」

Q1 显示四个失败 episode 各只发生**一次**非法穿越，之后再无合法穿越 → 超时。
需要确认这是**控制器不会做**，还是**几何上做不到**。

**做一个脚本化诊断即可，不需要控制器演示**：把追踪器放在入口面以内、走廊锥以外，
命令它先退到入口面以外，再从盘内合法穿越，检查 `terminal_latched` 是否触发。

- **能触发** → 记录下来。这是 SAC 未来可以演示、MPC 演示不了的具体能力（发一个后撤航点再重进）。

## 3. F3 给 S4 的窗口选择加一道可行性检查

### 问题

上一轮把「固定等 152.4 s」改成「取第一个窗口」，同时"先下降再重定位"被划进留白。
这两条放在一起是矛盾的：固定长等待其实一直在充当安全裕度，取消它之后时间被压缩，
而又不许下降到便宜的半径去转，于是所需角速率超过推力能撑住的向心力 → **被甩出去**。
S4-R 的 2/5（报告块）与 3/5（开发块）distance failure 就是这么来的。

### 修法（可行性，不是最优性）

窗口选择时加一道**硬可行性检查**：

```
候选窗口 w 在 t_w 到达，需要的方向重定位角度 θ，当前半径 r
所需平均角速率      Ω = θ / (t_w - t_now)
推力可持续角速率上限 Ω_max = k * sqrt(a_axis / r)      a_axis = 5/106 = 0.04717
若 Ω > Ω_max  ->  跳过该窗口，取下一个局部极小
```

`k` 取一个固定裕度系数（建议 0.7），**一次定死，不随 seed 或结果调整**。

**这条线要守住：规则可以拒绝不可行的窗口，不可以在可行的窗口之间排序。**
「比较第一窗口和第二窗口哪个更省」仍然留白给耦合层 —— 那是 SAC 的份额。

### 验证

3 seed 重跑，看 distance failure 是否消失。目标形态是**慢但不飞出去**，
不追求快、不追求省油。

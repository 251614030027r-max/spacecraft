# 反馈机制开发：执行落地的价值仲裁与执行等价经验（规格与判据，2026-11-20）

**授权：** 用户 2026-11-20（"自行判断推进设计，交下层测试"；要求：闭环、可验证的性能、体现一定算法创新、有包装空间，不是新的工程手段）。本文件先于实现入库；判据事后不改。

**基线：** `ROUND2.md` 的 ECC：保持 / 最近关键意图修正 / 末次经过的直接入口，标准 SAC，机会可达性势函数。

## 1. 问题：第一稿协调的两处开环

1. **修正时只看几何距离。** 关键窗口有多个可兑现候选时，按 ‖b − a‖ 取最近者。可兑现只是执行层模型下的模式切换，不等于捕获（DEAD_ENDS O7）。哪个候选在真实执行中更可能兑现、更省时省燃料，执行层不知道；学习器的价值知道，却没有参与。
2. **学习器只从提议本身学。** 被协调映射到同一执行动作的不同提议，在协调后的决策过程中转移完全相同（`facts/05` 命题 2(ii)）。但经验池里只有实际提出的那一个，等价类里其余提议的价值要靠函数逼近慢慢"猜"。

两处都是执行层知道、学习侧没用上的信息。下面的机制把它们闭环。

## 2. 机制

记关键意图机会集为 O_I(x)（`ROUND2.md` 第 2 节：可兑现、最后机会、燃料够用的网格意图），Q̄(o, b) = min(Q_1, Q_2)(o, b) 为当前评价器（双评价器取小，抑制高估）。

### 2.1 执行落地的价值仲裁（决策侧，`arbitration = 'value'`）

协调规则只改"修正时选哪个"：

1. 若 ê(x, a) = 1：执行 a（保持，不变）；
2. 否则若 O_I(x) ≠ ∅：执行 argmax_{b ∈ O_I(x)} Q̄(o, b)（并列时取 τ̂ 小者，再按网格顺序）；
3. 否则：末次可用经过时启动直接入口（不变），否则执行 a。

**分工：** 执行层回答"能不能"，即候选集只含它预测能兑现的意图；评价器回答"值不值"，即用真实回报学到的价值在这些候选里择优。何时干预不变，仍只在原意图接不上、且是最后机会时。

### 2.2 执行等价经验（学习侧，`equivalence = True`）

一次决策被修正或启动直接入口后，执行层的网格评估已经给出每个网格意图 b 的模式预测，因此可以知道哪些 b 会被协调映射到同一执行动作，即等价集 E(x)：

- **价值仲裁下的修正：** 所有原预测无事件的网格意图，都会被映射到同一个 argmax，因为选择不依赖提议。所以 E(x) = {b ∈ 𝔅 : ê(x, b) = 0} ∪ {ã}。ã 本身是关键意图，有事件，按规则保持，结果相同。
- **最近距离规则下的修正：** E(x) = {b ∈ 𝔅 : ê(x, b) = 0，且其最近关键意图（同一并列规则）为 ã} ∪ {ã}。
- **启动直接入口：** O_I 为空，所有无事件的网格意图都映射到同一个直接入口，E(x) = {b ∈ 𝔅 : ê(x, b) = 0}。

**做法：** 对 E(x) 中每个不同于提议 a 的 b，把同一条真实转移 (o, b, r̃, o′, d) 存入一个**等价经验池**。
- 不另行仿真；
- 不计入决策数（训练预算仍按真实决策计）；
- 每条真实转移的更新次数不变；
- **只进入评价器的回归：** 每次更新时，评价器的批量在原有的 256 条真实样本之外，再加从等价经验池抽取的 k 条，k = min(256, round(256 · N_eq / N_real))，即按两池样本数的自然比例、至多一比一（N_eq、N_real 为两池当前样本数）；
- 策略的更新只用真实样本批量，与基线完全相同。

**为什么精确：** 在评价器固定时，协调映射 𝒞 是 (x, a) 的确定函数。𝒞(x, b) = 𝒞(x, a) 则 P_𝒞(· | x, b) = P_𝒞(· | x, a)。所以补充样本是同一决策过程的真实样本，不是预测或反事实。这正是它与 D39–D43（反事实标签、校准机会图）的区别：那里学习的是执行层的近似判断，这里只用到执行层的确定映射。

**近似之处（如实说明）：**
- 等价判定用的是网格评估中 b 的那一行预测；若 b 作为提议，会另做一次原意图预测，两者只差求解器缓存的 ~1e-8 数值；
- 价值仲裁随训练中的评价器变化，所以协调后的转移核在训练中缓慢漂移，与分层强化学习中低层策略变化造成的非平稳同类（HAC）；经验池里较早的样本对应较早的仲裁。评估时评价器固定，映射确定。

**修订（2026-11-20，实现后、任何训练之前）：** 最初的写法是把等价样本直接混入主经验池。40 步冒烟中，等价样本与真实决策之比约 4 : 1（157 : 40），而且集中在每回合一两个关键状态上。混入主经验池会同时改变策略更新的状态分布，而在这些状态上，提议对执行已经没有影响。因此改为上面的"只进入评价器、至多一比一"。冒烟只用于检查流程，不涉及任何性能结果。

### 2.3 闭环

执行层预测 → 给出可兑现集 → 评价器在集内择优 → 真实执行 → 执行层的等价判定把一次执行扩展成等价类上的精确样本 → 评价器更新 → 下一次择优。

执行层的同一次网格评估，在决策侧和学习侧各用一次，不增加执行层计算。

### 2.4 性质（供论文）

1. **最小干预不变：** 干预的时机与第一稿相同；保持与直接入口的条件不变。
2. **映射确定：** 评价器固定时 𝒞 是 (x, a) 的确定函数，命题 2 的两条结论照常成立。
3. **等价样本精确：** 由第 2.2 节，补充转移服从同一核 P_𝒞。
4. **价值仲裁下，提议在关键窗口内对执行无影响：** 原意图接不上的所有提议映射到同一执行动作。策略不必在关键窗口内学会精确的意图，关键窗口的选择由评价器负责。

### 2.5 与已否定方向的区别（DEAD_ENDS）

| 条目 | 当时的做法 | 这次变了什么 |
|---|---|---|
| D19 | 两个连续价值择优 | 价值只在执行层预测可兑现的有限候选集里排序，可行性不由价值判断 |
| D37 | 执行层可行作为价值下界 | 不改价值目标 |
| D38 | 执行层机会信号给评价器排序 | 方向相反：评价器给执行层的候选排序 |
| D39–D43 | 学习执行层的近似判断（标签、校准、优势） | 只用执行层的确定映射生成精确样本 |
| D36、D41 | 执行器动作引导探索、改动作梯度 | 探索与策略梯度都不变 |

### 2.6 包装与定位（写作参考，不是论断）

- **"能 × 值"：** 与 SayCan 的思想同构：低层可行性筛选高层提议，学到的价值在可行集内择优。我们把它放进 RL–MPC 的连续控制，可行性来自执行层自己的模式预测，而不是另学的可供性函数。
- **事后动作改写：** 与分层强化学习的 HAC 同源：让高层按真实执行学习。区别是我们的样本精确等价，不需要 HAC 的"高层回报与低层执行路径无关"假设。
- **MDP 同态与动作等价：** 执行层给出状态相关的动作等价类，学习器用它做精确的数据扩充。
- **可迁移：** 任何"学习提议 + 确定性仲裁 / 屏蔽层"的结构，都能用这两部分。不依赖本文的特定观测或物理量。

## 3. 配置（`METHOD_REGISTRY.json`，`dev` 阶段）

| 配置 | 仲裁 | 等价经验 | 其余 |
|---|---|---|---|
| `ECC`（基线） | 最近距离 | 否 | 同 `ROUND2.md` |
| `ECC_FB`（本机制） | 价值 | 是 | 同上 |
| `ECC_EQ`（只用等价经验，备选） | 最近距离 | 是 | 同上 |

新开关默认 `arbitration = 'nearest'`、`equivalence = False`，此时与 `ROUND2.md` 的 ECC 逐位相同；用 `evidence/R2_EQUIV` 的脚本复核含修正与直接入口的回合。

**实现要点：**
- 采集进程不持有策略。价值仲裁时，采集进程把候选发给学习进程，学习进程用当前评价器给出各候选的 Q̄，再由采集进程按规则选择；
- 评估时由加载的模型直接给出 Q̄；
- 只有 SAC 配置可以开价值仲裁。

**TensorBoard 增记：** 每回合等价样本数、价值仲裁次数、价值仲裁与最近规则选择不同的次数。

## 4. 开发轮与判据（预先登记）

| 项 | 设置 |
|---|---|
| 阶段 | `dev`：种子 0、1、2；3000 次决策；评估初始条件 295300–295395（96 个） |
| 第一场 | `ECC` |
| 第二场 | `ECC_FB` |

**通过判据（对 X = `ECC_FB`，第三场时 X = `ECC_EQ`）：**
1. 捕获(X) ≥ 捕获(ECC) + 5（288 个任务中）；
2. 不安全(X) ≤ 不安全(ECC) + 1；
3. 3 个种子中至少 2 个满足 捕获(X, 种子) ≥ 捕获(ECC, 种子)。

**结论：**
- `ECC_FB` 通过：正式实验的 ECC 用 `ECC_FB`；
- `ECC_FB` 未通过、`ECC_EQ` 通过：用 `ECC_EQ`；
- 都未通过：正式实验的 ECC 保持 `ROUND2.md` 的形式，结果报告用户再定。

**都要报告：** 逐种子捕获、超时、不安全、真实回报；仲裁改变选择的次数；等价样本数；悬停信号（D03）。

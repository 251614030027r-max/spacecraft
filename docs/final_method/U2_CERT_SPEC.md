# U2 决策时认证（Executor Mode Certification）——规格与预登记判据

**状态：** 用户 2026-11-07 批准。U2 的执行器探询（`env/t2_probe.py`，与 RUN_U2 相同的网格、时域与执行器规则）从"训练期 critic 输入"改为在决策时认证 SAC 的意图。

- 判据在评估数据产生之前登记于本文件与 `experiments/cert_readout.py`。
- 机制只在开发开局 294000–294047 上调试；评估用新开局 294220–294267。
- 代码：env 0.15.0（`T2StageEnv._certify`，开关 `certify`，默认关闭，此前所有路径不变）；评估 `experiments.final eval --certify`；注册表阶段 `u2c`。

## 1. 机制

在每个阶段决策，SAC 给出意图 a 后：

1. 执行器用自己的阶段层、2 s 入口规则与条件 G★，按恒角速度模型推演 a 与 9 个固定探测意图（3 × 3 网格），最多 3 段（48 s），得到各自的模式切换（入口被接受或进入下降）及其时刻。
2. **只在三条同时成立时介入：**
   - a 在时域内没有模式切换；
   - 某个探测意图有，且入口到达不晚于"期限 − 45 s"；
   - **过顶约束成立**：该切换时刻再加一个自旋周期 2π/|ω|，已晚于"期限 − 45 s"。也就是说，错过这次过顶，期限前不会再有可接受的入口。
3. 介入时执行满足条件、且离 a 最近的探测意图（距离相同取切换更早的）。只管这一个阶段，下一次决策仍由 SAC 提出。
4. 其他情况原样执行 a。

认证不计算价值，不产生学习信号，是状态与意图的确定函数。

## 2. 理论

1. **改进命题（条件性）。** 设执行器模型在时域内准确，过顶约束成立，并且错过本次过顶即超时。那么原意图 a（在该次过顶中保持）以超时结束，认证意图以概率 p 进入入口并捕获。只要 p · (捕获价值 − 超时价值) 大于两意图在该阶段的代价差，认证不降低价值。这与选项框架的中断改进定理（Sutton、Precup、Singh 1999）同构，也与 C1 的"刚性承诺可行集 ⊆ 窗口承诺可行集"对称：认证后能赶上的过顶集合，包含原意图能赶上的集合。
2. **误差界。** 认证误判（预测能切换、实际没有）的损失，至多是一个阶段的代价差。阶段 A 实测：与真实执行的平衡准确率 0.918，近场真负例识别率 0.81。
3. **不打扰非约束情形。** 过顶约束由执行器自己的期限余量与自旋模型判定。期限宽松时（经济任务）条件不成立，不介入。
4. **可迁移。** 只需黑箱调用执行器自身的模式门槛与规划器。任何带离散模式切换的分层规划器或 MPC 都可以用同一认证：固定探测集、有限时域、模式事件、约束判定。

## 3. 评估（阶段 u2c；不训练）

- **模型：** 预实验的 EACH、SAC（种子 10、11；SHA256 见 `evidence/final_pretest/REGISTRY_RESOLVED.json`）。
- **开局：** 新开局 294220–294267（48 个）。
- **配置：** 每个模型认证关闭、开启各一次，同一检查点、同一开局。
- **配对：** 按种子、按开局配对，共 96 对。

**判据（`experiments/cert_readout.py`）：**

| 比较 | 作用 | 判定 |
|---|---|---|
| EACH + 认证 对 SAC | 论文主张：反馈对无反馈 | G1–G5（`experiments/u2_readout.py`）→ `pass` / `no_gain` |
| EACH + 认证 对 EACH（同一模型） | U2 认证的贡献 | `pass`（G1–G5）/ `improved` / `no_effect` |
| SAC + 认证 对 SAC（同一模型） | 不依赖 U1 时的贡献 | 同上 |

`improved` 须同时满足：
- 均值 > 0；
- 每个种子 ≥ 0；
- 紧急捕获 ≥ +1，总捕获不减少；
- unsafe 为 0；
- 经济任务均值差 ≥ −2。

## 4. 保底（事先登记）

**触发条件：** EACH + 认证 对 EACH，以及 SAC + 认证 对 SAC，都判为 `no_effect`。

**做法：统一信息边界后重训一轮。**
- 决策层观测去掉执行器派生量：上一段的位置与速度残差、保持标志、制动余量（第 14–16、18 维；代码中的 `geometric` 接口）；
- 所有组同时生效，从零重训；
- 执行器知识只经反馈通道进入：U1 进 critic，U2 认证进决策。

**依据：** 决策层不依赖执行器内部状态，可与别的执行器搭配。不是只削弱基线。

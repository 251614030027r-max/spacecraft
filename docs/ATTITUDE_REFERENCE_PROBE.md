# 姿态参考探针：262006 的指向假设被证伪（2026-09-12）

**结论：不要把姿态参考当作下一个单因子。** 它既救不了 262006，
在 262005 上也只是把一种失败换成另一种。这一条候选可以从队列里划掉。

产物：`logs/attitude_probe_20260912/summary.json`，12 局，固定设定点、无上层、
串行、`guidance=fixed`，只改 `precapture_attitude_reference`。
文中引用的每一个标量都在该文件里；逐步 trace 有 7.5 MB，未提交，

## 1. 为什么做这个探针

T6 记录过：262006 可解（离线可行性计划 217.5 s 完成、七类约束零真值违约、
视场裕度 0.693 rad），但四类上层**位置**决策共 90 余格全败，且全部死于视场。
由此提出的假设是：

> 它的失败是**指向失败**，位置通道说不到这件事上；换一个姿态参考也许能救。

下层 MPC 有三种姿态参考模式（`frozen` / `swept` / `aimed`），
`frozen` 是"实测最好"的默认值。本探针把三种都跑一遍。

## 3. 三条读法

### 3.1 指向假设对 262006 **被证伪**

三种姿态参考全部失败，而且 `aimed` 让它死得**更早**（34.9 → 10.7 s，29.7 → 8.5 s）。
所以"换个姿态参考就能保住视场"这个简单形式不成立。

论文里 262006 的写法应当收紧为：**在所测试的四类上层位置决策与三种姿态参考下，
该工况均未被救回；而一条零违约的可行路径确实存在。**
把它作为工况级的开放限制如实写，不要许诺一个未经验证的修法。

### 3.2 `aimed` 在 262005 上确实消除了视场失败——代价是别的地方

h20：96.0 s 死于视场 → **299.9 s 跑到时间上限**，失败原因换了。
h35：30.1 s → 211.1 s，但终止距离 **29.96 m**，即被推到 30 m 判飞出。

**视场不再是它的死因，但控制权限被挪走了。** 这说明姿态参考不是免费的：
把指向盯住目标，就得从平移那边借力气。在 Λ>1、共旋本身就要满三轴权限的工况下，
这笔账不划算。

### 3.3 `frozen` 与 `swept` 在固定设定点下**完全等价**

12 局里四组配对逐字段数值差异为零。原因是固定设定点的参考视线本身不扫，
`swept` 与 `frozen` 的差别无处体现。

因此仓库里"三种表述中实测最好"这句话，准确说法是**两种不同行为里取好的那个**。
论文与文档提到姿态参考时按这个口径写。

- **划掉**：姿态参考作为下一个单因子。

## 性能结论

原生判定no_gain。完整性、机制、终点和安全判据通过，效率E1及紧急捕获U未通过。四点平均EACC−SAC：seed0 −8.212150、seed1 +19.685933；紧急捕获累计差分别−7、+15。虽然两种子均值约+5.736891，预登记要求每个种子均为正、紧急捕获每个种子不为负，因此不能以总体正均值替代过门。终点分别−4.495481、+17.411984；seed0有1次unsafe、SAC为0，仍在已冻结容差内。修复解决实现错误，但稳定的独立收益尚未成立。

## 问题定位：目前证据支持到哪里

1. 价值排序与行为之间存在值得核查的断层。原生关键对准确率：EACC seed0为33.33%(12/36)、seed1为100%(26/26)，SAC为7.69%(2/26)、65.91%(29/44)。但EACC在真值可区分决策上的top1均为0，分母仅3和2个决策；关键对准确不等于找到了候选最优动作。既有JSON中的“critic所选候选相对实际动作真值收益”随附，可供核查Actor与critic的一致性，但不能据此直接批准Actor修改。

2. 不能把四组准确率解释成共同状态上的反馈因果增益。工具沿各检查点自身策略访问状态、生成自身候选，并由自身策略续飞真值；EACC/SAC汇总的状态、候选与后续策略均不同。执行书期待的“同状态同候选比较四种排序”只在每个检查点内部的四种评分间实现，跨检查点比较没有实现。原生自动解释中的“两个种子排序均优于SAC”只能视为各自分布上的描述。

3. 审计覆盖比48份开局文件看起来小。EACC两个种子仅15、13个审计决策，真值可区分的只有3、2个；36、26个关键对高度相关，不能按36/26个独立样本估计置信度。许多开局没有窗口内且满足模型标签生成条件的决策，详情见随附覆盖表。单靠这些读数不足以保证问题唯一落到某一行。

4. 候选差目标暂未显示稳定优势。非终止标签误差中位数：seed0绝对目标31.777862→候选差39.803527（增约25.3%）；seed1为22.500393→22.135049（降约1.6%）。没有支持“两种子共同误差明显下降”。而且当前diff对同一状态下所有未执行候选加同一个常数，因此diff_i−diff_j=label1_i−label1_j：它不能在该状态直接修复未执行候选之间的排序，主要影响绝对校准及候选相对实际动作的比较。若未来训练替换目标，是否通过共享critic间接改善排序仍是待验证假说。

5. 绝对目标误差包含估计对象不一致。审计label使用16个随机Actor动作估计含熵项的soft target V；真值则为确定性策略的折扣塑形奖励和，没有后续熵项。故误差并非纯粹的模型/自举预测误差，实际任务决策效用与训练软价值需要分开解释。label2也是直接两阶段展开，不是生产中的完整软Retrace加权目标；这限制对“融合失败”的归因，不否定原生性能评估。

## 给上层的优先建议（均待新执行书）

首要建议是先把诊断比较做成共同状态、共同候选、共同后续策略下的配对，并明确任务回报与soft价值两种估计对象；冻结状态来源、选点规则与覆盖门槛。当前已有JSON可先检查候选oracle空间、critic选优相对Actor执行的损失、成功/超时翻转及误差分布；补充JSON已给出前两项，无需新增仿真。共同状态数据不足的部分保留MISSING，不把不同策略轨迹冒充配对。

其次按种子分别解释：seed0标签准确率只有约0.5且critic更低，既可能信息不足也可能吸收不充分；seed1 critic关键对准确率高但top1为0，需要先看最优候选和实际动作的价值差。只有配对诊断支持相同瓶颈后，再选择一个最小改动对象。现阶段不建议仅凭汇总表就改Actor、加融合项或直接启用候选差替换。

不建议扩深预测、加直接下降或入口偏差补丁；不挑seed1作为成功结论，不追加训练或另选检查点。主张仍为执行反馈独立改善SAC长期决策，本轮no_gain应如实保留。

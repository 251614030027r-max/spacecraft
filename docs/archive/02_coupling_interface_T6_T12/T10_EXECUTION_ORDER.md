## 1. 补丁里已经做完的事（不要重做）

上层已经把下层的语义缺陷改掉并测完，补丁里包含：

1. **门控修正**（`controllers/mpc/constraints._predicted_terminal_active`）。
   原判据是一个轴向半空间 `p_x > -6`，**没有距离界**，所以离目标 16 m、离轴
   15 m 的飞行器也被强制执行进场走廊；那里线性化后要 4.13 个归一化单位的松弛，
   而 `constraint_slack_limit = 2.0`，于是 QP 报 `infeasible`，零推力回退把飞行器
   交给 `omega * r`。真值侧从不判这个区域。现在加了距离界
   `‖p‖ <= ‖port‖ + 4.5 = 6.0 m`，两项都是冻结任务参数，**不引入任何可调常数**。
2. **7 项新测试**（`tests/test_terminal_gate.py`），把"MPC 门控与真值门控一致"钉住。

5. **12 种子两时域的产物** `logs/terminal_gate/`。

## 5. S4：headroom 测试（本轮的核心，不训练）

问题：**同一个种子，换一个提交时机，结果会不会变。**

对 S3 中**未完成**的种子，扫提交时间：

```
for T in 20 40 60 80 100 120 ; do
  python -B -m experiments.evaluate_arrival_condition_script --horizon 35 \
    --policy commit_at --commit-time-s $T --seeds <S3 失败的种子> \
    --output logs/t10/commit_at_${T}.json
done
```

`commit_at` 在 T 之前发 `a = (-1, 0)`——保持**惯性冻结点**（等待必须是惯性的：
固定目标系点会跟着体固接近轴共旋，窗口永远不会打开），T 之后发 `a = (+1, 0)`。

**要报的量：**

1. **救援率**：S3 失败的种子里，有多少个存在**某个** T 能完成。
2. 每个被救种子的最优 T、完成时间、力冲量、非法穿越数。
3. 可行 T 的集合形状——是一个连续区间，还是散开的几段。
4. 反向代价：S3 **已完成**的种子里，有多少个会被非零 T 弄坏（抽 6 个种子跑 T=40 即可）。

> 机时估计：失败种子数 × 6 个 T。若 S3 失败约 15 个，则 90 回合，约 3–6 小时。

## 6. 闸门 B：这一轮的分叉

**有 headroom** ＝ S4 的救援率明显不为零（比如 S3 失败的种子里有三分之一以上
能被某个 T 救回），**且**可行 T 随种子变化（说明它是状态相关的，不是一个常数）。

- **有** → 继续 S5。
- **没有**（几乎救不回，或者所有种子都是同一个 T 最好）→ **停下报告，不要训练**。
  后者尤其重要：如果一个**固定常数** T 就能拿到全部收益，那就不需要学习层，
  写死即可，方法主张要重新设计。

## 7. S5：接口增益校准（只在闸门 B 通过后做）

已测出的问题：`∂r_ref/∂a0 ≈ -6.5 m / 单位动作`（因为 hold 半径冻结在 12–19 m 而
commit 半径是 3 m），而飞行器一个 2 s 决策窗、静止起步的平动权限只有 **0.094 m**。
死种子指令的每决策位移中位数是权限的 3–7 倍，执行器占用 0.84–0.95，净位移接近零。

校准目标：让典型策略动作变化引起的参考跳变落在 MPC 一个决策周期内能响应的量级。

**这是改 T6 冻结接口，所以必须：**

1. 自带单因子提交和 manifest；
2. **重新验证 `a = (+1, ·)` 的逐位 Pure MPC 地板**——12 种子 × 300 控制步，
   `max |Δwrench| = 0`。改增益很容易碰坏它，碰坏了整个接口的能力底线就没了；
3. 校准完**立即冻结**，不再反复调。

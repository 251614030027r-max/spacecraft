## 3. 算力：串行单进程、关闭事后诊断、seed 262000 前 300 控制步

| 时域 | mean | p95 | max | 超 100 ms 的步 |
|---|---|---|---|---|
| h20 | 42.02 ms (0.42×) | 47.53 ms (0.48×) | 226.1 ms | **1 / 300** |
| h30 | 62.67 ms (0.63×) | 68.21 ms (0.68×) | 326.8 ms | **1 / 300** |
| **h35** | **72.15 ms (0.72×)** | **77.44 ms (0.77×)** | 371.9 ms | **2 / 300** |
| h50 | 106.20 ms (1.06×) | 113.59 ms (1.14×) | 627.0 ms | **269 / 300** |

### 关于 max：它是冷启动，不是复发性质

四个时域的最差一步**都是第 0 步**。次差一步分别是 68.6 / 73.3 / 109.7 / 128.9 ms。
所以 max 那一栏描述的是首次求解的一次性代价，飞行系统只付一次。
**论文里报 max 必须注明它落在第 0 步**，否则读者会以为这是每秒都可能发生的尾部。

### 真正把 h35 和 h50 分开的不是 p95，是超预算步数占比

p95 只差 1.14× 对 0.77×，看着像"稍微超一点"。但**超 100 ms 的步数是 269/300 对 2/300**——
h50 是几乎每一步都超时，h35 是几乎每一步都不超。这个二元对比比 p95 更有说服力，
建议作为论文里的算力主证据。

`status_counts` 在 h35 上为 300/300 `optimal`，无回退。

## 4. 这张表怎么用

- **Pure MPC 行取 h35**：燃料最优（167.2 N·s，比 h50 省，比 h30 省）且在实时预算内。
- **h50 作为"非实时长时域参考行"**，说明延长时域的收益递减：完成数 9→10/12，
  代价是超预算步从 2/300 涨到 269/300。
- **主论点不靠算力**：{262005, 262006} 在四个时域下同样失败，
  而 h50 只超预算 1.14×——**加长时域既不是买不起，也解决不了问题**。
  算力是旁证，不是承重墙。

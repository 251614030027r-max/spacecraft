## 2. "数据不足"这个假设：**只对了一半**

- **对的一半**：数据增加 5 倍以后，V_L 的留出 R² 从负数变成了正数，各个头的最佳轮次从 0–8 推后到 23–67，说明网络确实开始学到东西了。421 的一致率从 48.6% 升到 77.1%。
- **错的一半——真正要紧的地方没有改善**。M6 里的"关键检查点"指的是两个分支一个成功、一个失败的状态，只有在这里仲裁才真正起作用。三个模型在这些点上的判对率是 **57% / 50% / 50%**，和掷硬币差不多。逐点看【交付，`m6_r2.json` rows】：
  - 在关键点上，μ_L − μ_B **几乎总是正的**（+0.5 到 +14.5），不管实际上赢的是哪个分支；
  - 学习分支赢的时候，价值就"判对"；学习分支输的时候，价值就"判错"；
  - 最典型的是校准开局 262119：学习策略在三个模型上都是硬失败（G_L − G_B ≈ −30），三个模型的价值在 0/10/20 三个检查点上却全部判学习更好（+4.6 到 +12.0）。

  **结论**：价值差里装的主要是一个常数偏好（学习策略平均更快完成，所以 V_L 的均值更高），并没有"在这个状态下哪一方会成功"的区分信息。R² 的提升来自拟合了"还剩多少路、多少时间"这类量，而不是拟合了成败。

  补数据改善了拟合，但没有带来区分能力。**再补一轮数据不是根因修复**，不建议再走。

## 3. 仲裁在 48 个开局上实际做了什么【上层计算，探索】

仲裁 R1 和 R2 只在 7 个开局上结果不同：

| 开局 | Pure | learned-only | R1 | R2 | R2 的决定 |
|---|---|---|---|---|---|
| 262004 | 完成 | 超时 | 超时 | **完成** | 第 73 步交回 → 救回了丢失 |
| 262035 | 超时 | 超时 | 超时 | **完成** | 第 28 步交回 → 两者都失败的开局被救成 |
| 262025 / 029 / 039 | 超时 | 完成 | 完成 | 超时 | 开局时 V_L 不确定 → 选了 Pure → 丢掉了 3 个救回 |
| 262045 | 完成 | 完成 | 完成 | 超时 | 第 36 步交回 → 反而丢掉了 |

第二轮的交回动作真正发生了。262035 是本轮第一次出现"两边单独都失败、组合起来却成功"的情况，说明交回这个机制是有能力的。但开局时变得更保守，损失了 3 个救回；净结果是 −2。

**唯一的违规回合 262027**，以及**丢失的 262015**，在 learned-only、R1、R2 三行里的走法完全一样：

| 开局 | 第 0 步 | 此后 | 结局 |
|---|---|---|---|
| 262027 | L 13.4±1.0 对 B 8.8±0.3 → 选学习 | 第 8 步 L 的均值已经降到 3.3，低于 B 的 8.1，但 σ_L 涨到 6–17 | 始终留在学习分支，非法进入后视场硬失败 |
| 262015 | L 16.1±1.4 对 B 9.9±2.2 → 选学习 | 从第 4 步到第 56 步，L ≈ 6±10，B ≈ 9±1 | 始终留在学习分支，距离硬失败（而 Pure 能完成） |

**这是仲裁规则本身的缺陷，与数据无关**：
- 开局时的规则是"不确定就选 Pure"，这是保守的；
- 交回时的规则是"只有确信 Pure 更好才交回"，也就是"不确定就继续留在学习分支"，这是**不保守的**；
- 而学习分支恰恰是会发生硬失败（−20）的那一方。

在这 48 个开局上，4 个 learned-only 失败回合在前 20 步里的最大 σ_L 都 ≥ 5.8；30 个成功回合里有 28 个 ≤ 3.9。也就是说，学习分支正走向失败时，集成网络内部的分歧会明显变大，但现行规则把这种分歧当成了"留下"的理由。

（注意：这是在已被看过的块上发现的规律。M6 校准块上 σ_L 与误差的相关只有 0.12 / 0.12 / 0.01，因为那里只看 0/10/20 三个早期检查点。**它不能作为结论，只能作为下一版设计的动机。**）

## 4. 结构性事实（跨两个独立块，较稳）【交付 + 上层计算】

| | 262000 块（48） | 270000 块（48，M2 数据） | 271000 块（192，仅学习策略） |
|---|---|---|---|
| Pure MPC 完成 | 37 | 37 | — |
| 262420 / 421 / 422 学习策略完成 | 42 / 33 / 38 | 44 / 39 / 37 | 81.8% / 75.0% / 83.3% |
| 学习策略救回 Pure 失败（三个模型） | 8 / 3 / 7 | **8 / 8 / 8** | — |
| 逐开局取优的上限（Pure ∪ 学习） | 45 / 40 / 44 | **45 / 45 / 45** | — |
| 学习策略的硬失败（视场/距离/终端） | — | — | **9.4% / 9.4% / 7.8%** |
| Pure 的硬失败 | 0/48 | 1/48（视场） | — |

1. **互补性在独立块上稳定复现**：三个模型在 270000 块上都救回了 8 个 Pure 失败开局，取优上限都是 45/48。这是目前最硬的正面事实。
2. **学习策略的完成率与 Pure 相当或更高，但它的失败方式不同**：Pure 失败几乎都是超时，而学习策略约 9% 是硬失败（视场、距离）。
3. 所以组合的真实问题很具体：**让学习策略去跑它擅长的部分，并在它走向硬失败之前把控制权交给 Pure MPC**。现行的价值仲裁问的是"哪边期望效用更高"，这个问题它答不出来（见第 2 节）。它真正需要回答的问题是"学习分支是否正在走向硬失败"。

## 5. 对论文的影响

- **现在不能写**："方法成立"、"仲裁提高了完成率"（三轮仲裁分别是 42、42、40，都没有超过 learned-only 的 42）、"耦合无效"（到目前为止价值只在 1 个模型上通过了校准）。
- **现在可以写（都要附产物）**：
  1. 参考路径修复带来的燃料消融；
  2. 互补性在两个独立块上复现（上限 45/48 对 37/48）；
  3. 学习策略的失败模式与 Pure 不同（硬失败对超时）；
  4. 负结果：固定策略价值回归在关键状态上没有区分能力，而且补数据不能修复。这个负结果本身有价值——它说明"用学到的价值做长时域仲裁"在这个任务上的瓶颈在哪里。
- 仲裁 R2 的燃料和时间代价是目前最小的（+65 s、+0.71 m/s）。这是交回机制带来的副效应，可以作为观察记录，但不能作为结论。

## 6. 下一步：需要用户定方向（上层建议 B）

> **已被取代（2026-09-30）**：本节的方向建议已撤回，见 `docs/V3E_STATE_REVIEW_20260930.md`。

以下两条路都是方法层面的改动，都需要预注册，都要**换新的正式评估块**（262000 块已被三轮设计看过，从现在起只作补充），并在新块上重跑 Pure MPC（冻结代码）。

- **A. 继续走价值仲裁，把回归改成成败分类**：每个分支估计 P(完成) 和 P(硬失败)，校准标准改成关键检查点判对率。
  - 风险：第 2 节表明，在 t = 0 时成败可能本来就很难从状态里预测（预检探针已经测过成败对目标相位很敏感）。如果真是这样，任何开局时的仲裁都达不到 45/48。
- **B.（建议）以风险触发的交回为主**：学习分支默认执行（它的完成率 ≥ Pure），另有一个"硬失败风险"判断器；风险超过预注册阈值时单向交回 Pure MPC（Pure 的硬失败率约 0–2%）。
  - 风险判断器用学习策略轨迹上"未来 N 个决策内是否硬失败"来训练。这种标签比"整回合成败"密集得多，而且越接近失败越好预测，正好对上第 3 节观察到的现象。
  - 交回后 Pure 能不能接住，用已有的交回探针数据来估计。
  - 这仍然是"RL 决定怎么做任务，MPC 保证安全"。但叙事要从"以基线为锚、有把握才偏离"改成"以学习为主、有风险就交还基线"，基线保留改由交回机制来保证。**这是论文叙事的一处改变，需要用户同意。**
  - 最小可行版本：不改 SAC、不改 MPC、不改任务，只新增风险判断器和交回规则，训练数据用已有的 M2/M2x 轨迹。

无论走哪条，都要先做一件事：把现行规则里"交回时不确定就留下"的不对称性，作为一个具名缺陷记录下来（本文件第 3 节）。之后的任何规则都不能再让"学习分支的不确定性"成为留在学习分支的理由。

## 1. 这一轮回答的问题

> 让学习策略在训练中就知道"随时可以把控制权一次性交给 Pure MPC"，并且学会什么时候交，最终闭环能否比 Pure MPC 干净完成更多开局，同时不毁掉 Pure 本来能完成的开局？

与 C_STOP 的区别：阶段 C 是在冻结策略上事后拟合一个"交接安全"分类器，策略本身不知道有这个选项；这里策略、交接价值、停止头一起从零训练，策略可以主动把飞行器带到"交出去很划算"的状态。

**不变**：任务、约束、时间上限、奖励各项（时间 0.01/s、完成 +20、失败 −20、势函数权重 0.05）、V3e 接口（`task_state_v3`、0.40 m 参考步长上限、近场下限）、Pure MPC、观测（42 维）、SAC 的网络和其余超参数。

**改变**（共三处，都是方法本身）：
1. 停止头 β(s) 与交接价值 Q_H；
2. 决策折扣 0.99 → 0.999（SAC、停止价值、势函数整形三处一致）；
3. 训练预算按**外层决策点**计（每次"继续"或"交接"决策计 1），每个外层决策一次梯度更新，与 V3e 相同；交接后的 Pure MPC 后段只给 Q_H 提供标签，不占预算、不产生任务策略更新，其计算量单独统计。

## 2. 方法（只此一个定义，代码 `train/stopping.py`）

| 部分 | 定义 |
|---|---|
| 任务策略 | 原 V3e 的 SB3 SAC 二维动作，接口不变 |
| 停止头 | β(s) = P(现在交给 Pure MPC \| s)，伯努利策略，输入完整 42 维观测，网络同 SAC（4×256 ReLU） |
| 交接价值 | Q_H(s)：Pure MPC 从 s 飞到回合结束的**实际**折扣回报，蒙特卡洛回归，不自举。只用与策略无关的 31 维（core + 目标姿态 + 剩余时间，同阶段 C）。双网络取小 |
| 继续价值 | SAC 双 critic：Q_C(s,a) = r + γ·V(s′) |
| 状态价值 | V(s) = β·Q_H + (1−β)·V_C + α_stop·H(β)，V_C = E_a[min Q_C − α log π] |
| 停止头更新 | 最大化 β·Q_H + (1−β)·V_C + α_stop·H(β)（离散 SAC）。最优时 β = σ((Q_H−V_C)/α_stop)，V 等于 Q_H 与 V_C 的软最大值，即 V = max{Q_H, V_C} 的熵正则形式 |
| α_stop | 0.005，与任务策略固定的 `ent_coef` 相同，不引入新温度 |
| 初始化 | 停止头最后一层权重置零、偏置 −5：所有状态初始 β = 0.0067/决策（100 个决策内不交接的概率 0.51）。只是初始化 |
| 部署 | 第一次 β(s) ≥ 0.5 时交接，之后一直由 Pure MPC 飞（单向，切换时重置 MPC）。0.5 是伯努利的众数，即离散动作的确定性策略，不是调出来的阈值 |

**后段标签**：一次交接跑完整个 Pure MPC 后段，后段经过的每个状态都以自己的折扣剩余回报作为 Q_H 标签。交接点的标签是精确的；后段中间的状态由"没有在此处重置"的 MPC 飞，与"在此处重置后接管"只差求解器容差（探针：262004 上两者每决策奖励最大差 2.2e-4，结局相同）。

## 3. 两个工程问题及处理（训练期，不影响部署）

**(1) 行为停止 vs 目标停止。** 训练初期任务策略很差，Pure MPC 好得多，理性的停止头会在所有开局的第 0 步就交接；此后再也采不到"继续"的数据，任务策略永远学不好，形成自我确认的塌缩。因此训练时交接按 `clip(β(s), 0.002, 0.01)` 采样：
- 上限 0.01：β 再高，任务策略也能继续飞到中后段（100 个决策内不被截断的概率 0.37）；
- 下限 0.002：β 很低处也偶尔交接，给 Q_H 留标签，避免"不确定就一直学习策略"的已知偏向。

两套价值都是离策略的（Q_H 是固定控制器的蒙特卡洛回归，Q_C 通过目标 V 自举），截断只改变采到什么数据，不改变估计对象。部署只用 β。

**(2) 预算与更新次数（2026-10-02 修正，开发 run 之前）。** 交接在一次环境步内跑完后段。`num_timesteps` 计**外层决策点**：每次继续或交接决策计 1，每个外层决策做一次梯度更新（`learning_starts` 之后），与 V3e 相同。后段决策只产生 Q_H 标签：不计入预算，也不产生任务策略 / Q_C 更新，因为后段里没有新的"继续"转移。否则会出现"学习转移少于 V3e、却在旧数据上多做更新"的情况，任务策略变弱时分不清原因。后段计算量记在 manifest 的 `suffix_simulated_decisions`，墙钟时间因此比 V3e 多，预计 1.2–1.5 倍。SB3 预热期（前 2000 个外层决策）的连续动作仍是均匀随机，与 V3e 相同；停止决策在预热期按初始化的 β 采样。

**(3) 后段标签的真实性核验（开发 run 之前，上层在沙盒中完成）。** 在 280000–280003 四个开局上，交接前分别有 0 个和 10 个学习决策（随机任务动作），在交接后第 2、8、16 个决策处比较两条路径：MPC 不重置继续飞，与在该处重置 MPC 后接管。通过条件：所有比较点的干净完成结局一致，且折扣回报差 ≤ 0.5（成败相差 40 的奖励单位下）。工具 `experiments/v3_stopping.py labelcheck`，结果见 `eval/stopping/label_check/`。通过则后段状态全部作为 Q_H 标签；不通过则只用交接点的精确标签（预先写定的退路）。

## 4. 折扣改为 0.999 的依据

| 路线（按任务奖励） | γ = 0.99 | γ = 0.999 |
|---|---:|---:|
| 快而冒险 | 9.6 | 14.7 |
| 慢而可靠 | 7.0 | 17.2 |

0.99 下 150 个决策后的完成奖励只剩 0.22，偏好快而冒险的路线；0.999 下剩 0.86，完成优先，早完成的压力来自任务本身的时间代价。0.99 当初是针对"悬停吸引子"选的（`train/hybrid_configs.py` 文档），当时奖励里的完成奖励被折扣得太小；现在奖励已有时间代价，且停止选项的价值比较需要接近不折扣的尺度，这个理由不再适用。

## 6. 正式训练与评估

| 项 | 内容 |
|---|---|
| 训练 | 种子 262430 / 262431 / 262432（原为 E 预留，从未训练），各从零 60,000 个外层决策；代码就是开发 run 的提交 |
| 评估块 | **267000–267047**（原为 E 预留，从未使用） |
| 行 | `pure`（一次，与模型无关）；每个模型的 `stopping`（方法）；每个模型的 `learned`（同一策略、禁止交接，只报告） |
| 模型 | 各运行的 `final_model.zip`，不挑检查点 |

**每个模型的通过条件**（与阶段 C 相同，三条同时满足）：
1. stopping 行干净完成数 **>** Pure MPC 干净完成数；
2. stopping 行真值违规回合数 **≤** Pure MPC；
3. 被毁掉的 Pure 成功开局（Pure 干净完成、stopping 没有）**≤ 2**。

**总判定**：
- `FIDELITY_FAIL`：文件不全、提交不一致、工作树不干净、截断或模型文件混用；
- `METHOD_HOLDS`：≥ 2 个模型通过；
- `METHOD_DOES_NOT_HOLD`：否则。

**同时报告（不作门槛）**：三行共同干净完成开局上的时间和 Δv（与阶段 C 相同的效率规则）、交接时刻分布、从不交接的回合数、learned 行、救回 / 毁掉的开局。

**必报：协调增益**（readout 的 `coordination_gain`，stopping 行相对同一模型禁止交接的 learned 行）：干净完成数之差、相对 learned 行救回 / 毁掉的开局、共同干净完成开局上时间和 Δv 的中位变化。读法写在前面：
- 若 learned 行本身已与 stopping 行一样好或更好（例如 Pure 37、stopping 42、learned 45），只能说"停止感知训练改善了任务策略"，**不能**说实际交接改善了闭环；
- 交接本身有贡献，至少要满足一条：stopping 比 learned 完成更多；完成不降而时间 / Δv 明显下降；对 learned 失败有明确救回且毁掉很少。

## 7. 边界

- "最坏退化为 Pure MPC"不是保证：停止头可能在错误时刻交接或不交接，判据 3 专门检查毁掉了多少 Pure 成功开局。
- 阶段 C 的读数（第 0 步时仅凭状态区分 Pure 成败的 AUC 0.45）提示 Q_H 在开局处可能不准。这是已知风险，本轮不为它加模块；结果由正式评估说话。
- 1000 个 Pure 开局的诊断（Pure 从开局的成败是否有可学的初始状态结构）可以并行做，只用于论文解释，不是开发 run 或正式训练的前置门。
- 论文数字只来自第 6 节：全新训练种子、全新块、新块上重跑 Pure MPC。开发 run 和 262000/266000 块都是开发验证。

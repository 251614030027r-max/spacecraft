## 1. 已经验死的结论(不要重开、不要回头再测)
在当前"温室版"任务(single_phase)上,经**四轮无训练探针**,**SAC-MPC 耦合没有可占的缺口**:
- 配置良好的**短 horizon(h10)+ local 线性化约束凸 MPC**:又快(p95≈0.42×)、又安全(20/20、相位泛化)、又鲁棒(抗±30%惯量、抗相位、抗5°姿态误差;时延/低更新率经 EKF predict 可补)。Pure SAC 不安全(三seed 3/1/0)。
- 四探针:①学习凸终端值(有害,函数类错)②相位采样(陈旧∝冻结|ω|)③模型失配(误差∝horizon²)④部分可观(**曾以为是唯一缺口,实为注入 bug**:0.05°偏置把7.6km/s轨道速度泄漏成~6.6m/s假相对速度;修正后5°偏置无害,时延可被EKF补)。下层在投训练前逆利益揪出此bug并撤回——**流程自洁,结论可信**。
- **第一性原理(独立于测试、与四探针一致)**:模型已知且准 + 状态已知 + 有好参考(手工走廊)+ 凸约束 + 短horizon够 → MPC 在此regime数学上近最优,RL 只添不安全。**MPC 赢是任务性质,不是测试错误。**

**⇒ 明确禁止:回温室任务造第五个探针;硬找小众点把 hybrid 塞进去;把"路线A"当出路。**

## 2. 转向的核心判断(为什么以及往哪转)
- **"耦合更好"只在"MPC 有真实短板"时成立。** 我们把任务建得让 MPC 没短板,所以补无可补。别人能发 RL-MPC,是因为他们的任务保留了一个我们抹掉的难点(上海交大=cost难设计;北航编队=参考难;南航=多障碍死锁;领域=接触/未建模/感知)。
- **出路:把这个任务里被抽象掉的、真实存在的、MPC 天生搞不定的"一个"难点放回来。** 这是"把过度简化的任务还原成忠实任务",是正当动机,不是补丁。
- **第一性判据**:光滑/凸/可建模/低维的难点 → MPC 赢;RL 只在**非光滑 / 非凸组合 / 未建模 / 高维**时才真正赢。任何"光滑凸参数"版都会再次塌缩成"MPC 赢",别再选那类。

## 3. 候选的 MPC-hard 难点(保持任务形态)
| 候选 | 为何 MPC-hard / RL 赢 | 评级 |
|---|---|---|
| **A. 真实离散推力器(控制分配)** | 固定推力器簇/开关/PWM/最小冲量 → 分配是混合整数(非凸组合),MIQP-MPC 昂贵非实时;RL 天生学分配。**已测出绑定资源就是推力**,难点落在绑定处。**让"MPC太慢"的compute故事第一次成立在真问题上**(不再是可避免的线性化artifact),安全耦合也成立(RL提离散分配,MPC/QP兜连续安全) | **首选** |
| B. 未建模目标动力学 | 柔性附件/晃动/真未知惯量(在线辨识来不及收敛)→ MPC模型错就违约;RL跨分布鲁棒。主流"安全RL"无争议赢法,只因我们用完美刚体才没显现 | 次选(建模量大) |
| C. RL 供共旋参考(去手工走廊) | 攻"手工走廊"拐杖 | 弱(可能塌缩成"MPC加长horizon也能规划") |
| 障碍场 | 硬约束避障是 MPC **强项**,只有"多障碍死锁"一小块是RL的,不够干净 | **不推荐** |

**上层推荐 A**。但这是战略选择,**须先与用户确认 A/B**,不要替他定死。

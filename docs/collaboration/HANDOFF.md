## 1. 我们在做什么

**研究对象：** 有限推力的追踪航天器，对快速三维自由翻滚的非合作目标做六自由度近距离安全预捕获。

**体系：** SAC 在低频审议点选择长期任务意图 → G★ 把意图变成可执行的条件最小 Δv 计划，并管理计划的保持、修订与恢复 → **同一个**受约束 MPC 以 0.1 s 全程执行 → 训练过程中，真实执行与 MPC 预测的信息回到 SAC 的价值学习。

**论文要证明的是训练内的双向耦合，不是架构拼装。** "高层 SAC + 低层 MPC"本身、"先训练 SAC、再接 MPC 修补"、交接切换、事后轨迹补救，都不构成充分的新颖性。

**最短主线（三窗口共识）：**

> 课题不是追求"RL + MPC 架构"，而是训练过程中 SAC 的长期任务决策与受约束 MPC 的执行 / 预测之间有效的双向耦合。历史上 F01、T1 v4、T1-L 说明：只靠接口拼装、重规划控制或 critic 修复，不足以支撑论文。T1-L 稳定了，但学习增益被强固定 G★ 规则压缩；T1-O V2 尝试放大任务选择自由度，又在独立确认集上暴露"动作有用，但状态自适应选择的价值未被证明"。用户希望在真实六自由度物理和公平对照下，合理调整任务难度与 SAC / G★ 的优化职责，让策略拥有重要、自然、可观测的长期选择权，从而得到能真实显示学习进展和 TCPF 机制独立效果的论文实验。允许这种有学术动机的任务调整，不等于允许削弱求解器、伪造低 0k 或随结果调指标。TCPF 已实现的区间 Bellman、MPC 相对反馈和四臂归因结构是可复用的研究资产，不是已验证有效的方法结论。

**当前位置（2026-10-18）：** 机制已基本实现，但从未在一个有学习空间的任务上检验。两次学习空间检验（T1-L；T1-O V2，停于 Gate C）都没有找到"可由观测兑现、优于简单统一策略"的状态相关决策余量。实验全部停止，下一任务版本由用户与研究层讨论决定。

## 2. 论文层面的理论问题

### 2.1 方法主问题

对长时域、强约束的翻滚目标预捕获，要回答两件事：
1. 怎样让强化学习**真正负责物理上有意义的长期任务选择**，并且这些选择经条件规划器与滚动 MPC 实际兑现；
2. 怎样利用**训练过程中** MPC 的预测和真实执行信息，改进 SAC 对可执行任务意图的价值辨识与策略学习，形成可归因的双向协同。

**统一机制：TCPF**（Task-Consistent Predictive Feedback，任务一致性预测反馈；名字可改，问题不能散）：

> SAC 选择长期任务意图 → G★ 对该意图做高质量条件可行规划，并管理计划的采纳、保持、拒绝与恢复 → 同一个受约束 MPC 全程高频执行 → 真实审议区间反馈与可信的 MPC 局部替代预测共同参与 critic 学习 → SAC 根据更新后的价值改进下一次任务选择。

**机制的关键是"任务请求—实际采纳—持续执行—价值学习"四步语义一致。** 不能把"6 s 审议""SMDP""Huber 差分损失"包装成三个独立首创。

### 2.2 TCPF 的数学核心与理论边界

**复合状态：** z_k = (x_k, p_k, η_k)。其中 x 为真实系统状态；p 为已采纳计划及相应的求解 / 执行记忆；η 为审议时钟与事件。实际的 34 维神经观测**不等于已证明足够 Markov**。

**审议区间 Bellman：** 审议时刻 j 的动作 a_j 经过 d_j ≥ 1 个 2 s 物理宏步，才再次审议或结束。已执行区间的折扣目标为

\[
R_j=\sum_{i=0}^{d_j-1}\gamma^i r_{j+i},\qquad y_j=R_j+\gamma^{d_j}(1-D_j)\,\bar V(z_{j+d_j}).
\]

- 非审议的 continue 样本仍用真实一步 TD；
- 审议区间完整封账后才进入训练；
- success、unsafe、timeout 终止，不自举；数值失败是截断，单独处理；
- 多环境逐环境封账，不跨回合串联。

这是已有 SMDP / option / 多步 Bellman 在计划审议任务上的正确使用，**不是新的 Bellman 理论**。

**MPC 相对反馈：** 只在满足三个条件的审议状态上，构造一个 **2 s 局部**替代比较：替代意图真实可执行、与已选意图确有物理差异、模型 / 安全 / 模式门控可信。

\[
\widehat\Delta=(\hat r_{\tilde a}-r_a)+\gamma\,[\bar V(\hat z'_{\tilde a})-\bar V(z'_a)],
\qquad
\mathcal L_\Delta=\mathbb E\big[w\,\mathrm{Huber}\big((Q(z,\tilde a)-Q(z,a))-\operatorname{sg}(\widehat\Delta)\big)\big].
\]

- 锚点是真实已执行的一步 (r_a, z'_a)；替代动作的预测 (r̂, ẑ') 来自影子 MPC。
- 相对差可以抵消部分共同偏差，但后继 V̄ **仍来自同一个目标 critic**，不是独立的长期真值，也不是无偏长期优势。
- 预测误差、模式切换、安全门控、"替代动作是否会被 G★ 真正采纳"，都限制它的可信范围。
- 不能把 2 s 局部差分伪装成整段 6 s 审议乃至 300 s 的真实反事实。
- 必须同时报告：MPC 项对 critic 的有效梯度占比、样本覆盖、价值排序、最终闭环差异。加大辅助权重补不了错误符号或零覆盖。

**可以做的有限理论：**
- 在完整状态足够 Markov、持续长度与事件正确、折扣一致的条件下，证明审议区间 Bellman 的折叠恒等式；
- 在局部奖励预测误差、后继状态误差、目标价值 Lipschitz 等**明确假设**下，给 MPC 相对预测误差一个条件界，并强调其限制。

**不能宣称的：**
- 由这些恒等式推出全局收敛、递归可行、无条件闭环安全，或所有未执行长期计划的准确 Q；
- 套用普通 Bellman 收缩或基础 Q 分解当作新定理；从带软约束和数值回退的 QP 推出绝对硬安全；
- 熵项只存在于真实审议点，α×间隔只是现行时间密度近似，不是已证的精确熵率；
- off-policy 的行为回报 / MC 也不是当前策略 soft-Q 的无偏标签；
- UTD、学习率退火、Actor 降频、MC / 等价损失、Huber 形式都只是稳定化手段，不属于主创新。

**实现状态：** `TCPFSAC`、`IntervalReplayBuffer`、NΔ 相对项都已在科学代码中实现并通过技术核验。区间 TD 与 MPC 反馈的训练效果**从未被检验**：所有停止都发生在训练之前。

### 2.3 三层职责的学术定义与当前实现之间的张力

**SAC 应当学什么：**
- 在任务层对未来机会、时间与资源、计划是否持续做决策，承担能经实际闭环归责的长期目标；
- 只调一个"总是越小越好"的延迟，即使连续可微，学术上也只是参数搜索；
- 反过来，让网络直接输出六自由度推力，会回到历史上纯 SAC 样本稀疏、约束难满足的老问题（D01）。

**G★ 应当做什么：**
- 保持同一质量的目标旋转预测、给定任务条件下的 SCP 优化、与真实安全相关的可行性判断，以及旧计划保持、有限顺延和必要恢复；
- 记录请求、采纳、剪裁、拒绝、恢复和实际轨迹；
- **不替 SAC 按完整任务回报在多个合法长期意图之间自主择优。**
- 注意：现有 `τ_min_feasible` 主要是 G★ 在给定入口条件下搜到的最早可行锚点，属于可行性计算。不经核验，不能当作"G★ 已偷偷做了全任务最优"。

**MPC 应当做什么：**
- 在同样的 6DoF 动力学与约束下，以 0.1 s 执行跟踪与安全约束；
- 名义预测窗口只有 h35 × 0.1 s，远短于 G★ 几十到上百秒的计划和 300 s 的任务；
- 向学习器提供局部执行代价、约束压力、模型预测及其误差、可信替代动作的物理差，而不是凭一次 QP 给出未实施意图的长期真实性能；
- 规划成本、MPC 目标值、真实折扣回报是三种量，不能混用。

**可观测性：**
- 34 维审议观测包含几何、计划记忆、符号化跟踪误差、期限与时间余量；
- 但首次决策时用于把延迟动作换算成绝对交会请求的 `τ_min_feasible` **不在观测中**。这可能让与时间 / 预算相关的选择难学，但不是已证明的 Gate C 根因；
- 若要补入锚点或可行成本摘要，必须在决策前只读求得，并考虑在线求解开销、所有比较策略的信息公平、计划记忆是否充分；
- 不得用真值未来回报做观测；"加特征之后变好"不能自动归因于 MPC 反馈。

**审议频率的价值（不能忘）：**
- 每 2 s 都让 SAC 重新决策（T1 v2 / v4、T1-L B2）会退化：Actor 后期偏好推迟，critic 高估（D26）；
- 6 s 审议加事件审议（T1-L N0 / NΔ）稳定跑完 40k。说明高频 MPC 滚动与高层任务改写不应共用同一频率；
- 但 6 s 不是数学最优周期；硬编码 keep 也不能声称"SAC 学会了保持"；
- 计划失效或安全恢复之后要有事件触发和明确状态；Replay 里 continue 记录的必须是实际执行的动作，而不是未被采用的 Actor 输出；
- 有效审议样本数要与 2 s 真实宏步数分开计量。

### 2.4 学习空间：五个互不等价的命题

这是一条连续的证据链，不是"五项贡献"，也不意味着必须在正式训练前人为设置五道硬门：
1. 存在合法、可执行的替代任务意图；
2. 该意图改变了实际的 G★ 计划和 MPC 真值闭环，而不只是改变名义动作或规划代价；
3. 不同意图的优劣**随状态而变**，且相对一个强、固定、公平的规则有足够大的净空间；
4. 这种变化能被**决策时可用的观测**分辨，并能被真实 SAC 在合理样本预算内学到；
5. 加入 MPC 预测 / 执行的训练反馈后，相比同接口的普通 SAC，有额外、独立的性能或样本效率优势。

**三个常被混淆的反例：**
- **存在可行解 ≠ 存在值得学的策略差。** G★ 让所有固定候选都完成，只说明架构好；如果所有开局的最优都在同一个角点，SAC 只会缓慢逼近那个角点。
- **动作改变轨迹 ≠ 自适应价值。** 同一开局上，τ / κ / v_in 的变化会影响时间、Δv 甚至成败；但如果每类状态都偏好同一方向，固定常数就够了。
- **逐开局事后 oracle − 最佳统一 ≠ 可由观测学到的增益。** oracle 看到了未来结果，并且在已观察样本上择优；在线 SAC 只能看当前状态，状态分布还随策略变化。少数极端失败样本还会让终端罚放大 oracle 差。所以 T1-O 的 2.62 不是学习上限，更不是收益。

**策略真正应拥有的责任**是不同状态下的任务偏好：何时交会、等待 / 继续 / 修订、合理的进入条件，以及时间与资源之间的取舍，而不是不断扰动一个已经很好的计划。稀疏审议只改善时间一致性，不能凭空创造原任务里不存在的状态相关优化需求。

**0k 强弱与学习空间是两件事。** 0k 不强，任务仍可能不可学；0k 很强，也可能在燃耗、时间或任务机会上留有空间。要看的是：自然可达的较优闭环策略与 0k 之间有足够差异，而不是预定 0k 应该是百分之多少。

### 2.5 归因：证据层次与论文图

| 证据对象 | 可以证明 | 不能冒充 |
|---|---|---|
| Pure（固定终端参考 MPC）对同物理的 G★ 规则 | 长时域条件规划框架相对这种 Pure 的价值 | SAC 的学习收益，或"所有经典 MPC 都弱" |
| 零步 SAC → 训练后 SAC（同任务、同评估） | 相对自身初始化是否学得更好 | 必然超过强非学习规划策略 |
| 训练后 SAC 对同接口的强固定 / 非学习状态规则 | 学习是否得到实际可归因的净决策价值 | 训练内 MPC 反馈的独立作用 |
| 同接口有 / 无区间 TD | 时间一致学习目标的独立影响 | MPC 辅助的独立影响 |
| 同接口有 / 无 MPC 预测辅助 | MPC → critic 训练反馈的额外效果 | G★、场景或奖励改变带来的收益 |
| 多种子、未见过的独立开局、额外 CPU | 稳定性、泛化、计算代价 | 单种子 × 32 开局就能给出的跨种子保证 |

**三个因果台阶，任何一级没有证据都不能跳过：** ① G★ 架构相对 Pure；② SAC 相对 0k、相对最强合法固定 / 状态规则和预测代价规则的净贡献；③ 同环境、奖励、动作、网络、训练预算下，可信 MPC 相对项的独立贡献。

**主张要按证据收窄：**
- 共享修复（如 G★ 期限保护）后各臂都成功，只能算共享可行性修复；
- critic 损失下降而控制回报不变，只能算"信号已进入代码"；
- 优势只出现在样本效率或稳定性、而非性能终点时，论文主张要准确限定；
- "执行修复成功 → 价值学习改善 → 同接口带反馈的臂显著优于无反馈的臂"是三个不同命题，不能互相替代；
- 两臂之间若同时改了多个因素（如 T1-L 的 B2 与 N0，审议频率与目标时距同时不同），差值不能严格归于单一机制。

**四臂归因结构（方法备忘，不是自动获批的执行单）：**
- O-R1：审议 + 一步 TD + 无辅助；
- O-R3：审议 + 区间 TD + 无辅助；
- O-Δ1：一步 TD + MPC 辅助；
- O-TCPF：区间 TD + MPC 辅助。

四臂共用任务、网络、样本资格（`uniform_eligibility`）与预算，只在两个开关上不同。交互项 I = (TCPF − R3) − (Δ1 − R1) 只有在多种子数据支持时才能解释为正协同，不能因为方法叫 TCPF 就预设它最好。

**文献边界：** AC4MPC（Actor / Critic 引导 MPC）、Wu 等 2024（MPC 辅助价值估计）、北航编队（RL 机动时序 + MPC）、上海交大 2026（神经代价 / MPC 反馈的航天器控制）、南航 2026（安全约束双层 MPC）都已存在。所以"首次 RL + MPC""首次把 MPC 信息用于 RL""首次低频 RL 规划航天器"都不能主张。可区别之处只能是经实际验证的"请求—采纳—区间执行—可信价值反馈"组合，及其相对强规则的净收益。正式投稿前需针对最终方法重新做新颖性审查（参考文献说明见科学分支 `References/README.md`）。

## 3. 由理论问题引出的场景问题

### 3.1 物理任务本身的矛盾

有限推力、有限完成时间、快速三维自由翻滚的非合作目标；随目标转动的体固连捕获端口；姿态—平移耦合；碰撞、视场、操作球与端口锥、制动包络、末端捕获保持。

离线可行轨迹、在线 G★ 条件规划、短窗 MPC 数值可行、**真实 RK45 闭环的最终成功、时间与 Δv**，是四件不同的事。理论主线是"局部约束可行 ≠ 剩余时域内可捕获、可经济完成"。

**设想的科学逻辑（待在新载体上证实）：** 快速翻滚使可交会窗口、所需时长与推进剂随端口几何状态变化；MPC 只保证局部约束控制，并不自动解决长时任务时序；G★ 给出可执行的条件任务集合；SAC 从中学习状态相关、可兑现、超越强统一规则与无学习预测规则的任务意图；MPC 在执行中提供受约束的预测反馈，改善学习效率或最终性能。

但**长时域需求不自动证明必须用 RL**：强的模型预测 / 规划和非学习反馈规则也可能解决。论文必须说明比较的 Pure 是什么，不能笼统说"MPC 都不行"；强规则是必须面对的反证，不是不能出现的对照。

### 3.2 为什么现有 T1 载体不足以验证 TCPF

这是当前主线上最关键的一环：

- **0k 太强，提升太小。** G★ 让未训练策略接近强固定规则。T1 v2 零点 16/16、81.02，几乎等于无学习最早规则 16/16、81.09。T1-L 零点约 79.7，强规则 82.45；训练 40k 只涨 1.6–2.1，仍低于强规则。
- **最优在动作角点。** T1-L 的强规则在"延迟 0、κ 1.0、v_in 0.02"这个边界上；六条规则逐开局 oracle 只比最强统一规则多 +0.21。修好后期退化，也只是更快逼近这个角点。
- **放大动作范围没有创造状态相关价值。** T1-O V2 把首次延迟放宽到 0–90 s，并把燃耗权重提到 20。动作确实改变执行与收益，但在独立确认集上，最优几乎总在同一端：更早交会、途中保持、κ 取上界、入口速度取下界。可观测状态规则与"总是最早"A0 打平（−0.03）。

**研究解释（待证）：** 瓶颈可能是**任务决策价值的来源和职责划分**，而不只是动作范围不够大。"G★ 吞没了学习空间"目前只是需要按动作映射逐项核对的结构假说，不能当作全部根因。也可能是当前确定性物理任务与已选的 τ / κ / v_in 本来就偏好同一个角点。不能通过放大 λ、延长延迟上限或反复换确认集去找 PASS。

### 3.3 用户允许的任务调整及其边界（10-17 至 10-18 明确）

**允许：** 在真实、有解释力的航天任务范围内，有物理依据地**适度增加任务难度**，或调整真实任务定义与资源权衡；**重新划分 SAC 与 G★ 的决策权**，让学习策略承担重要的、随观测状态变化的长期任务决策。目的是得到有真实动态范围、可解释的训练现象与论文图。旧文档里"不修改任何物理 / 任务参数"的说法，原意是防止事后制造 SAC 优势，**不再绝对化为下一版的禁令**。

**仍然禁止**（早期约束全部有效）：
- 削弱 Pure MPC，或加入只对 Pure 不利的障碍、走廊；
- 提高翻滚率造成不可恢复的距离违约来制造差距；
- 修改安全判据、删除困难开局；
- 根据结果调整训练 / 测试权重；
- 把规划器或场景能力的变化记为耦合算法的收益；
- 以"结果好看"为目的的非公平改动。

**"降低 G★ 能力"的准确含义：** 降低的是它对**上层任务性能选择的包办程度**，把任务偏好、资源—时间取舍、交会机会与修订时机等有价值的权力交还 SAC。**不是**减少 SCP 节点、降低求解精度、放松 MPC 约束、故意给劣质轨迹、关闭危险情形的恢复，也不是单方面把非学习基线调差。

**固定规则不要求 100% 捕获：**
- 有些合法状态下，固定时机失败、另一合法意图成功，这恰恰可能体现需要状态选择；
- 但如果所有候选都因推力不足、远场失控、30 m 越界一起失败，那是**控制可达性瓶颈**，不是可学空间；
- 失败结局可以进入训练和统计；不能为了让固定规则"全成功"而无限缩小难度，也不能刻意让随机 0k 失败来制造"从低到高"。

**场景服务于方法：** 论文主创新仍是训练内 SAC–MPC 协调。任务重构只是为它建立可信、不过度饱和的验证载体，不能喧宾夺主变成"如何设计更难场景"的文章；场景贡献与方法贡献必须分开报告。

### 3.4 设计新任务时已知的物理与工程约束

- **远场外漂是 G★ 的风险，不是学习问题。** 高翻滚率加低纬度视线时，MPC 跟不上 G★ 计划 → 偏差 > 1 m 重规划 → 全推力恢复 → `hold:infeasible` → 30 m 越界（原 T1-O 工况试探 6/20 unsafe，P1 1 次，D28）。若新任务加难远场，先做物理筛选；修 G★ 需要单独论证，不能混进算法消融。
- **G★ 的规划 Δv 只含转移段**，不含驻留与下降，系统性偏向长等待；以它为依据的择时基线表现很差（Gate C 中相对 U 为 −9.28，另有 1 次 unsafe）。
- **κ 与 v_in** 在 T1-L 和 T1-O 上几乎单边偏好（κ 1.0 对 0.7 为 15:1，v_in 0.02 对更高为 27:4）。若保留为 SAC 动作，需要研究层确认其意义。
- **锚点网格粗**（20–30 s 一档），"延迟 0"本身带有量化余量。
- **换燃耗权重后，** 反事实门限 e_r = 0.06（在 λ_f = 5 标定）失效，必须重新标定（Gate E 工具已备好）。
- **不同任务之间回报不可直接比较**：T1-O（λ_f = 20）的回报不能与 T1-L（λ_f = 5）的 82.45 比；T1-L 的 Pure 2.50 不能换成旧 T1 的 0.91。

## 4. 用户的诉求

### 4.1 论文层面

- **论文类型：** 以可解释、可复现、方法结构紧凑和可信物理对照支撑的航天器控制 / 强化学习交叉论文；现实目标是可靠的中科院二区。
- **真实的学习现象：** 从真实 0k 到训练后有可见、连续、物理合理的进步，且不过早饱和。具体包括：
  - 学习曲线；
  - 捕获、时间、推进剂；
  - 状态相关的动作；
  - 机制消融的差异；
  - 代表性 6DoF 轨迹、接近入口、任务切换、真实力与角度、安全裕度、时间—Δv 权衡；
  - 必要时 Q 对动作的排序、影子预测的可信度与额外计算量。
- **"图要好看"的正确实现：** 图可以设计得清楚、信息密度高，但数值必须来自全部保存的检查点和同样预注册的评估。
  - 不平滑掩盖后期回落；
  - 不挑最好种子、不选最佳检查点；
  - 不只统计捕获回合的燃耗；
  - 不用奖励缩放或燃耗权重制造漂亮斜率；
  - 不改初始网络。
- **"0k 成功率高、训练只涨 1–2 分"不再被视为满意的论文载体。** 成功率很高时，可以用可靠的连续指标和样本效率说话；但"高成功率、极小燃耗下降"是否够一篇论文，要重新评估，不能无条件认定足够。
- **不要求：** 强固定规则 100% 捕获；控制器零步必须失败；学习曲线严格单调。早期"捕获率提高约 10 个百分点"只是愿景，不是事后调阈值的指标。
- **要求：** 实际任务确有自然的状态依赖收益空间，完整方法确有可重复的学习增量。
- **自主学习：** 时间、Δv、成功、违规、超时有明确的回报合同。不为了让 SAC 更早、更多等待、少重规划而加密集的手工偏好奖励；奖励不编码答案。

### 4.2 工程层面

- **速度：** 用户很看重推进速度。训练耗时高，反对"改一点 → 摸底 → 长训几十小时 → 又换假设"的循环。重活放在下层本机（12 核）；能并行就并行，尽早完成。
- **门控与真实训练的平衡：**
  - 技术正确性与风险性的物理辨识要做足：程序可运行、可重载，动作在物理上真实生效，安全裁判与公平对照没有意外变化，实验可追溯；
  - 学习收益、收敛与算法净贡献，不能完全靠小型规则和门槛替代真实训练；
  - 既不能把每个研究不确定性都变成训练前硬门（早期教训），也不能在不存在可学价值时白耗大训练（T1-O V2 的 Gate 提前发现了问题）；
  - 训练前的技术冒烟可以验证 Replay、模式、终止、自举、模型重载、影子预测不污染真实状态；"网络一定能超过最强规则""MPC 辅助必有独立增益"只能在真实训练和独立评估中下结论；
  - 是否先做小规模试学、做到什么程度，由用户决定。
- **集中审查：** 下层完整交付 → 上层集中核验 → 再定冻结与训练。不给上层无限任务，不靠反复训练前筛选替代已授权的完整实验。
- **本机运行：** 绝不弹窗（用户多次因误关弹窗中断实验）；只保留一个科学工程 `D:/py/DRL2`；第一篇论文的工程 `D:/py/DRL` 不得动。
- **Git：** 只保留三条分支；Git 只记事实，不记讨论。
- **沟通：** 中文，简洁；先结论，再关键数字和证据位置。

## 7. 三个窗口的职责与执行纪律

### 7.1 职责与工作链

| 角色 | 职责 |
|---|---|
| 用户 + 协作窗口（研究层） | 定研究问题、成功标准、方向与授权；协作窗口负责讨论、记录思想、指出过度归因与方向偏移 |
| 上层 | 审查方案的可行性；实现科学代码与测试；预注册判据；冻结 SHA；写可直接执行到交付的执行单；核实下层交付并写审查；维护科学分支文档、`PROJECT_STATE.md`，并按用户要求整合本文件与研究演进 |
| 下层 | 在授权范围内于用户本机自主执行准入、基线、校准、训练与评估；交付原始数据；维护 `CURRENT.json` 与本机资产 |

**工作链：** 研究层授权 → 上层实现、核验、冻结 → 下层本机执行、交付 → 上层集中审查 → 研究层决定下一步。没有明确 GO，不自动启动训练。

*历史文档中的"A"指协作窗口；"B"指曾提供独立意见的另一个讨论窗口。*

### 7.2 三窗口共同红线

- **真值 RK45 几何是唯一的安全裁判**；观测、QP "solved"、预测裕度都不算。
- **Pure MPC 冻结**：不改 Q / R、时域、走廊、终端或容差，除非是有名的代码缺陷；每个正式块都重跑。
- **不制造差距**：不加人为障碍、无动机的噪声，不缩短时域、不限推力、不用错误模型，不定只伤基线的规则；奖励不编码答案。
- **每次训练从零开始**（不续训、不热启动）；作结论需 ≥ 3 种子并报告分布；不换种子、不挑检查点、不丢失败种子。
- **每个实验只改一个可解释的因素**，单独提交，附 manifest。
- **评估确定性、串行**；并行耗时不作实时性声明。
- **进入决策或论文的数字必须指向产物**（JSON / CSV / manifest / 提交 / 脚本），否则标为探索性。
- **开发验证 ≠ 论文正式验证 ≠ 飞行认证**；冒烟测试只查正确性，不定方向；单个种子或探针不能改变研究问题。
- **正式块 300000–999999 从未访问**，未经授权不得访问。
- **停止规则由当轮已授权方案决定**：不因看见不漂亮的中间曲线就改任务或停训，也不因沉没成本修改确认集、λ 或阈值后声称同一预注册通过。
- **FAIL 即停**：不改阈值、不追加候选、不换开局去追 PASS；原判定原样保留。可以另立版本，但不改写旧结果。
- **Git 只记事实**：代码、已执行的执行单、结果、证据、总账、交付、审查进入 Git；方向想法、提案、讨论留在对话里。提案只能作为授权执行单进入 Git，结论只能连同其产物进入。
- **提新方向前**，先说明原负结果（`docs/DEAD_ENDS.md`）的哪一条条件发生了本质变化；不给旧路换名重跑。

### 7.3 协作窗口

- 记录用户诉求、思想与论文主线；指出过度归因和方向偏移。
- 分开记录：用户已明确的诉求、源材料已验证的事实、协作窗口的待证解释、只提出过而未采纳的构想。
- 不能用助理意见覆盖用户意图。历史上协作窗口曾因丢失部分中间聊天，过度强调"不准动场景"和"必须先用简单规则过数道门"，又在 Gate C 失败后立刻主张改成估计不确定性任务，都没有接续用户当时的思路。
- 不在用户决定前替上层持续提出新的任务单；不制定固定步数、候选或新 Gate 阈值。

### 7.4 上层

- **冻结在先：** 判据、候选、拟合方法、开局集都在第一个相关回合之前提交并推送，以提交时间为证；规则写在模块里，用命令机械执行。
- **操作化要披露：** 方案没给具体数的阈值，上层落成数字时要说明"这是上层的操作化"，并请研究层确认。
- **准入从简：** 只排除会让实验无效的程序或数值错误、动作或物理不生效、不可追溯的配置、明显不公平的对照。已通过的检查直接复用。不默认代跑大规模规则网格或长训；重活写执行单交下层，上层核实。
- **执行单要能直接转发**，写清当前任务状态与来龙去脉，让下层理解。
- **报告会破坏主张的问题时，按格式写：** 是什么；影响哪条主张；为什么不只是局限；最小检查；需要怎样的方法改动。可以质疑研究问题，但不能改写它。
- **数值纪律：**
  - 快照分叉一律 `sync(fresh_solvers=True)`，数值重复性要测出来；
  - 同一 Gate 的比较在同一台机器上做，跨机器只比较判定，不比较逐位数值；
  - 运行中不改被导入的模块（评估进程池每阶段重新导入工作树）；
  - 燃耗权重从 `info["delta_v_step_m_s"]` 精确重算，不为不同权重重跑物理。
- **证据：** 只以单个文件 `git add -f evidence/<ID>/`，附 SHA256SUMS；回合 JSON 打成确定性 tar.gz；模型 zip 不上传，只记 SHA。
- **沙盒限制：** 4 核、15 GB，单回合约 100 CPU 秒；不能推标签、不能删远端分支（交给下层）；长任务后台运行加完成通知，等待期间不跑占 CPU 的测试；容器可能重启，评估工具会跳过已写出的回合。
- **提交：** 末尾附 Co-Authored-By 与 Claude-Session 两行；提交和产物中不写模型标识；不开 PR。

### 7.5 下层

- **开始新任务前：** 先读新执行单，核对 Git、冻结代码、环境与文件 SHA、现有运行和进程身份，再动手。旧 PID 只作历史；以命令、创建时间、manifest、心跳共同核对。能复用的结果按新单条件复用，不重做已通过的准入。
- **授权内自主：** 常规的路径、换行、日志、编排问题自己修，不逐步请示；科学方案、阈值或授权的变化，以及实质技术失败，按执行单保留证据上报。不按回报好坏临时改参数、种子、预算、门槛，不挑检查点。停止条件以当轮执行单为准，不因中期回报低而停训。
- **资源：** 尽量并行、尽早完成；但并行环境数会改变采样 / 更新节奏，不能当纯资源开关去改已冻结的 `n_envs`。按新单做短资源探针，综合 RAM、磁盘、CPU 与评估积压；CPU 空闲不代表内存安全。中断后不自动续训或重跑（很多版本不保存 Replay 与优化器状态）。
- **绝不弹窗：** 后台任务用原生隐藏 PowerShell（`Start-Process -WindowStyle Hidden`）、直接科学模块和文件日志，必要时 Idle 优先级。不用 Minimized；不混用 `DETACHED_PROCESS` 与 `CREATE_NO_WINDOW`；不恢复旧 pythonw / runpy 包装。用户要求在 PyCharm 手动启动时，只交付可复制命令和日志查看方法。
- **低频监测：** 按阶段或约 30–60 分钟批量检查，状态不变就安静；只在启动、门槛、异常、中期 / 最终交付时通知。stderr 的数值精度警告不等于失败，看退出码、ABORTED、参数与日志增长。自动跟进当前为 PAUSED，只有用户授权才启用。
- **目录：** 新任务先建 `过程文件/<主题>/`，脚本、状态、锁、快照、控制台和临时产物从创建起就放主题内；根目录不散落文件。不为整理目录中断任务或移动活跃日志。被登记表、MODEL_SHA256 或回执引用的模型、日志、包必须保留，清理前先查映射。
- **Git：** 先 fetch，核对分叉、dirty 与远端，再精确提交授权范围内的文件。collab 只改 `lower/`、`CURRENT.json` 与总账的下层列；不代写上层判定，不从 collab 运行科学代码。协作助手 `过程文件/协作/脚本/协作助手.py` 使用前读帮助与白名单。禁止强推、擅改标签。CURRENT 按 JSON 原值保留（避免 PowerShell 把日期字符串转成本地时区），写后做语义比对。发布后核验远端提交与对象。Git 偶有 `unable to find all commit-graph files` 警告，不影响操作，不为消除它做破坏性修复。
- **交付：** 区分执行事实、上层解释、假设与未做项；"跑通"不等于"学习有效"。所有检查点如实交付；零点、调优强规则、Pure 基线同口径。并行输出的 wall_s 之和不是 OS 累计 CPU 时间，估算与实测分开写。每轮交付可独立判定：冻结版本、配置、样本、关键基线、判据、异常、边界、逐文件 SHA 与必需原始结果；模型只记 SHA。统一放 `上层交付/最新/`，旧轮核验后移入 `历史/`。大包传输范围按当轮授权决定（既有约定 > 50 MB 只给本机路径与 SHA）。

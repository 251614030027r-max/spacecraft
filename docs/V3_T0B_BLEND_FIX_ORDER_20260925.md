## 1. 诊断（沙箱实测）

脚本 `experiments/probe_v3_blend_stress.py`；产物 `eval/adp/v3_t0b_blend_stress.json`。

**方法**：目标系里的暂存方向 `h(t)` 只取决于目标翻滚和开局位置，与追踪器之后的动作无关。
所以对 12 个种子（263000–263011，不在任何评估块内）各记录一次完整 300 s 的 `h(t)`，
再在离线状态下，把训练式的任务状态序列回放给三种方向插值：
- 3 条常数 c（0.3 / 0.5 / 0.7）；
- 6 条随机游走（δρ ±0.5 m，δc +0.05 / −0.02，与 V3 动作上限一致）。

每条序列都施加与 env 相同的"同一时刻 0.40 m 度量上限"。

| 插值 | 失效位置 | 超过 3 m（108 条序列） | 最坏 |
|---|---|---:|---:|
| V2 最短弧 slerp | 暂存方向接近抓取方向的**反向**（148°–175°） | 39 | 18.0 m |
| T0 带记忆旋转轴 | 暂存方向**接近**抓取方向（3°–5°） | 26 | 31.7 m |
| **方向状态限速（本修复）** | —— | **0** | **2.95 m** |

T0 版本修好了反向点，却在另一端坏了。原因：
- 暂存方向接近抓取方向时，`h − d → 0`，旋转轴失去定义；
- 解卷绕后的角度可能已经累积到接近 2π，中间的 c 会把参考放到另一侧，并随轴一起翻转。

只有 `h` 曾靠近 `d` 到 5° 以内的 3 个种子（263000 / 263004 / 263005）出问题，这与训练中"部分回合、部分种子"出现大跳变的分布一致。

**结论：任何"只由 (h, d, c) 决定的方向公式"都会在某处不连续**。方向在单位球上从 h 到 d 的插值，没法在所有相对位置上都连续地定义。
所以不再找公式，改为**让施加的方向成为一个状态，限速跟随公式给出的目标**。

## 2. 修复规格

### 2.1 方向状态与每步更新

新增状态 `u`（单位向量，目标系），每回合 reset 时清空。每个 learned 决策：
```
g        = slerp_shortest(h, d, c)                    # 目标方向：V2 的无状态最短弧即可
max_ang  = 1.2 · |ω_target| · Δt + 0.40 / r           # Δt = 2 s，r = 本决策参考半径，|ω_target| 取当前目标角速度模长
若 u 为空：                u ← g
否则 若 angle(u, g) ≤ max_ang： u ← g
否则：                      u ← 沿 u→g 的最短弧转过 max_ang
参考 = r · u
```
- `|ω_target|` 用**当前目标角速度**，不用标称值。跨工况翻滚率更高时，允许的转角自动放大，c = 0 的惯性保持仍能跟上；
- u 与 g 恰好反向（夹角 = π）时，转轴取任意与 u 正交的确定性方向（沿用 `_fallback_blend_axis`）；
- c = 0 与 c = 1 时，只要跟上了，`u` 就严格等于 `h` 或 `d`（夹角 ≤ max_ang 时直接赋值）。

参考实现：`experiments/probe_v3_blend_stress.py` 的 `RateLimitedDirection`，以及同文件里的 `_geodesic`。

### 2.2 与同一时刻度量上限的配合（重要）

`_limit_task_state` 的二分会多次调用参考函数评估**候选**状态。**这些评估不得更新 `u`**：
- 写一个纯函数 `_direction_step(u_prev, g, max_ang) -> u_new`；
- 候选评估一律用上一决策提交的 `u_prev`；
- 只在决策最终施加时提交一次 `u ← u_new`。

沙箱压测就是这样实现的（`ref(state, commit_state=False)`）。

### 2.3 去掉带记忆旋转轴

`_v3_memory_axis_direction` 及 `_v3_blend_axis` / `_v3_blend_angle` 删除（或保留代码但不再调用）。
T0 中基于它的测试改为针对新实现。

### 2.4 验收边界改为按半径计算

原来的"< 3 m"是固定数，没考虑半径和翻滚率。新的逐决策硬边界：
```
|r_{k+1} − r_k|（目标系） ≤ 1.2 · |ω_target| · Δt · r_{k+1} + 0.40 m + 1e-6
```
在 25 m、标称翻滚率下约为 2.9 m；在 27.7 m 下约为 3.2 m。下层之前看到的 262421 "最坏 3.32 m"，有可能是在合法范围内的，按新边界重判。

## 3. 测试

1. **合成几何**（单元测试，秒级）：h 在单位球上匀速转动，分别以 3°、90°、177° 的最近距离掠过 d，另加一条正好穿过 −d、一条正好穿过 d。
   c 取 0.3 / 0.5 / 0.7 常数，再加一条固定随机种子的随机游走。每一步满足 2.4 的边界。
2. **端点**：c 恒为 1、跑足够多个决策后 `u == d`（差 < 1e-12），从而 `z = (ρ_max, 1)` 的参考严格等于 `desired_position`；c 恒为 0 时 `u == h`。
3. **候选评估不改状态**：连续调用 `_limit_task_state` 两次、中间不提交，`u` 不变。
4. **真实条件压测**（验收，分钟级，可并行）：
   - 用下层已有的 10k checkpoint（三个种子各一个），**随机策略**（与训练同口径），每个种子跑 12 个回合（种子 263000–263011）；
   - 用 T0.3 的 `reference_jump_target_m` 逐决策检查 2.4 的边界：**违例数必须为 0**；
   - 另外报最大跳变与 p99。
5. 原有全套测试仍绿；全程 baseline 逐步等于 Pure MPC 的地板测试仍过。

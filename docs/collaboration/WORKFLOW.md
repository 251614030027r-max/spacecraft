# 协作快速通道（2026-11-20 起；用户要求：少流程、少校验文件、快处理）

三层职责与共同红线见 [HANDOFF.md](HANDOFF.md) 第 4 节。本页只管"怎么快速交接"。

## 1. 执行书

- **开跑前可以原地修改**，不另开新版本。
- **开跑后的变动**写在文首的"追加（日期）"里。
- 执行书只规定做什么、判据和交付命令，不规定在哪台机器跑。本地与云端如何分工，由下层自行决定。

## 2. 开跑与交付：两条命令

- **开跑前：** `python -B -m experiments.final preflight --root <结果目录>`。它记录提交号、工作树是否干净、核数、版本和 pytest 结果；退出码为 0 即可开跑。
- **交付：** `python -B -m experiments.final pack --stage <阶段> --root <本地目录> [--root <云端带回的目录>] --output evidence/<主题>`。它完成：
  - 完整性检查；
  - 模型与原始结果的哈希；
  - 读数与预登记判定；
  - 训练小文件与 TensorBoard 日志；
  - RESULT.md。
- **云端只需带回：** 每个运行的 `manifest.json`、`finished.json`、`episodes.json`、`tb/`，以及 `final.zip` 或一行哈希的 `final.zip.sha256`，再加上评估结果 JSON。模型不必回传。
- **提交：** `git add -f evidence/<主题>`，提交并推送；把同一份 RESULT.md 放到 `lower/handoffs/<主题>/RESULT.md`。

## 3. 不做的事

- 不自制额外核验文件：VERIFIED、EXIT_RECEIPTS、SCOPE、历史对照哈希、TensorBoard 与原生记录比对、旧证据重算哈希等。
- 不做执行书没要求的核验。跨机器只比较判定，不比较比特。
- 开发轮不打归档标签，只在正式实验冻结代码时打。
- 不写解释性长文。只有异常（缺项、报错、中断、重复进程）才在 RESULT.md 末尾写一两句。

## 4. 状态与汇报

- **上层：** 维护 [PROJECT_STATE.md](PROJECT_STATE.md) 第 1 节一张表。
- **下层：** 只在开跑、完成、出异常时更新 `CURRENT.json`，五项即可：
  - 在跑什么（配置 / 种子 / 机器）；
  - 进度；
  - 预计完成；
  - 下一步；
  - 问题。
- **给用户的汇报：** 三行。
  1. 做完了什么；
  2. 结果（贴 RESULT.md 的表和判定）；
  3. 需要用户决定什么。

## 5. 工作链

研究层（用户 + 讨论窗口）授权 → 上层写规格、实现、测试、写执行书 → 下层执行、`pack` 交付 → 上层看 `SUMMARY.json` 和判定后给结论 → 用户决定下一步。没有明确 GO，不自动启动训练。

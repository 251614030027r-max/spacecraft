# 论文资料与写作取材指南

写论文时从这里**取事实**，表达按学术论文的写法另写。资料本身偏直白、偏细，有的地方为了准确会多写一句限定，这些不必搬进论文；名称与术语以 `facts/00_术语与符号.md` 为准。论文中不出现配置名、文件路径、提交号，也不出现"冻结""逐位等价"这类工程说法。

## 阅读顺序

| 顺序 | 文件 | 用于 |
|---|---|---|
| 1 | `facts/README.md` 与 `facts/00`–`07` | 方法部分（按常规论文顺序：术语符号 → 问题与建模 → 总体框架 → RWG → 执行层 → ECC → 学习算法 → 对比方法） |
| 2 | `EXPERIMENTS.md` 第 1–3、5–7 节 | 实验部分：研究问题、任务条件、训练组与对照、终点与统计、稀缺解释轴、图表规划（结果等正式实验交付后再写） |
| 3 | `BACKGROUND.md` | 引言：背景、两个问题、研究问题、贡献；与汇报稿的差异 |
| 4 | `References/README.md` 与 `References/` | 相关工作与表述参考；README 写明每篇用来做什么、不要声称什么 |

拿不准的事实回到代码核对：每个事实稿末尾的"代码对照"给出位置。

## 只在需要时查

| 文件 | 可用的内容 |
|---|---|
| `docs/DEAD_ENDS.md` | 开发期试过、未纳入方法的做法（讨论或附录用） |
| `docs/HISTORY.md` | 研究过程的时间线（不写进论文，只帮助理解为何是现在的方法） |
| `evidence/README.md` | 开发期结果的位置（只能作"开发期"出现，不并入正式结果） |
| 协作分支汇报稿 `wang24.pdf` | 背景与问题的原始表述 |

## 写作时不看

`CLAUDE.md`、`docs/engineering/`（复现命令、源码对照、审计）、注册表 JSON、协作分支的执行书与交付、各证据目录的原始文件。这些是工程记录，容易把论文写得过于工程化。

## 正式结果

正式实验交付后在 `evidence/FORMAL/`：`FORMAL_READOUT.json`（主终点、次终点、归因、机制统计）、`EPISODES.csv`（逐回合）、`FIGURES/`（F1–F7、T1–T3、RWG 几何图）。交付前论文中的结果位置用占位符，不填估计值。

## 1. 新增的规划权限

**入口速度是什么：**
- G★ 的终端约束是：到达随目标旋转的入口点 r_e（港口轴上 6.3 m），终端速度 v_e = ω×r_e − v_in·r̂_e。
- v_in 原来写死为 0.06 m/s，现在成为每个**新计划**的输入。
- 它是优化器的等式终端约束，不是奖励项，也不是控制器参数。

**动作与观测：**
- 动作 a2 → v_in = 0.06 + 0.04·a2，范围 [0.02, 0.10] m/s。
- a0（τ，v2 语义）和 a1（κ）不变。

**范围核实（在原范围内成立，不缩窄）：**

| 约束 | 数值 | 结论 |
|---|---|---|
| 入口点在口部区域内的目标系速度 | 等于 v_in，上限 0.35 m/s（`terminal_total_speed_limit`） | 满足 |
| 中间节点的径向制动包络 | 规划器仍逐节点施加 | 不受影响 |
| 下降段步速 | κ × Coriolis 上限（2.7°/s 时约 0.1 m/s），即约 0.03–0.10 m/s | v_in 与之同尺度 |

**何时生效：**
- 只有真正新建计划时（初次规划、重规划、恢复；recovery 规划器同样使用）才采用 v_in。
- 计划保存自己的 `entry_speed_m_s`。
- 保持计划时不受影响，也不会因 a2 不同而被迫重规划。
- τ 期限一致性、`kept:no_earlier`/`kept:infeasible_request` 保护、恢复与惯性保持逻辑都不变。

**观测：** 25 维，在 v3 的 24 维后追加当前计划的入口速度 (v_in − 0.06)/0.04。无计划（含下降）时为 0，由 `has_plan` 区分。

**日志：** `entry_speed_request_m_s`、`entry_speed_applied`、`entry_speed_plan_m_s` 写入 `info["execution"]`、`decisions.jsonl`（`v_req`/`v_applied`/`v_plan`）和开发评估的 `decision_log`。

**L_eq：** 只在 a0 的保持带内变动，a1、a2 保持不变（`test_keep_band_equivalence_holds_with_an_entry_speed_component`）。因此不会把会触发不同新计划的 a2 拉平。

## 2. M2 反事实覆盖新权限

**入口速度候选：**
- 真实动作的预测若会新建计划，且 (episode + decision) 为偶数，则唯一的替代动作只改 a2：a2 < 0 时 +1，否则 −1，即 Δv_in = 0.04 m/s；τ、κ 相同。
- 其余状态沿用原 τ 候选。原 τ 候选的 a2 与真实动作相同。

**有效性判定：**
- 两个动作都新建了计划，且两计划入口速度相差 ≥ 0.02 m/s，即为"物理不同"（`same_entry_speed` 关闭门控）。此时 Δτ_eff 可以为 0。
- 求解状态、全窗口真值安全、模式切换、饱和、近期限，以及预测误差 e_r/e_p/e_o 的门控**全部不变**。

**shadow 一致性：**
- 同步时复制 G★ 的 `entry_speed_m_s`、`deadline_margin_s`、`last_deadline`；计划字典随之深拷贝。
- `predict()` 与真实 `step()` 都通过同一个 `apply_intent()` 设置 κ 与 v_in。
- 观测由同一个 `_observation()` 生成，25 维。

**训练日志：** 每个反事实记录 `kind`、两计划的入口速度，以及门控原因。`experiments.t1_fix_readout` 输出每种候选的 candidate / physically_distinct / gate_valid 计数（曲线 4 的 `cf_by_kind_*`）。

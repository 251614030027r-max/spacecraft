## 0. 被测对象

"以 Pure MPC 为基策略的策略改进"要成立，需要两个前提：

- **P2**：`Q_b(s, o_K) − V_b(s)` 能把 V2 的救回行为和破坏行为分开。其中
  `V_b(s)` = 从 s 起一直 Pure MPC 的回报，`Q_b(s, o_K)` = 从 s 起先执行学习意图 K 个决策、再交回 Pure MPC 的回报；
- **P1**：被比较的标量回报与任务结局（完成 / 超时 / 飞出）同序。否则"回报更高"不等于"结局更好"。

仿真确定：目标翻滚、RK45、CLARABEL MPC 都无随机项，已由 V2 评估的逐步 wrench 复现和
262004 的沙箱逐步重放证实。**所以每个 rollout 给出的是该候选的精确值，不是估计。**

**回合**（按规则取，不挑）：来源 `eval/adp/final_v2_nominal_26241{1,2}.json`，与 `eval/adp/pure_mpc_nominal.json` 按种子配对。

**候选**：学习意图 = V2 当时**实际施加**的任务状态序列 `task_state_applied`，逐决策重放，每步断言重放出的施加状态与记录一致。本轮只用 β = 1；β 分级留到接口修好之后。

| rollout | 定义 |

**回报**：`G` = 按决策折扣求和，γ = 0.99（SAC 的 γ，env 已在每个决策内求好和）。同时记录不折扣回报、是否完成、完成时间、飞出、超时、真值违约。

## 2. 预注册判读

### 复现校验（先看，不过则全部作废）
- `B` 的 completed / survival 与基线行逐回合一致：27/27；
- `Kinf` 的 completed 与 V2 记录一致：27/27。

### P1：回报与结局是否同序
同一初始状态下的 4 个 rollout 两两比较；只统计结局不同的对（一个完成、一个没完成）。

| 观测 | 结论 |
|---|---|
| 完成的那一方 `G` 更高的比例 ≥ 95% | 回报可作仲裁标量 |
| < 95% | 回报与结局错位 → 仲裁标量改为与结局对齐的量（在评估器里单独定义，不改训练奖励），再读 P2 |

另外单独报：超时回合与完成回合的 `G` 分布是否有重叠（Pure MPC 的失败回合都是停在抓取点、超时结束）。

### P2：K 的硬门
以 `A_b = G(K) − G(B)` 为判据，取 `argmax{B, K}` 作为"精确仲裁"的选择。

| 观测（对某个 K） | 结论 |
|---|---|
| 救回组 9 个中，**≥ 3 个**在该 K 下完成（`K` 完成而 `B` 未完成）且 `A_b > 0`；**并且**破坏组和保住组里，精确仲裁丢掉的基线完成数 = 0 | 该 K **通过** |
| 否则 | 该 K 不通过 |

执行顺序：先读 K1。K1 通过则冻结 K = 1；K1 不通过则读 K5；K5 也不通过 → **暂停这条主线，不进入 V3 正式训练**，报告用户。
（K1 和 K5 的 rollout 一次性跑完以节省往返，但判读严格按这个顺序。）

阈值 3/9 的理由：救回组是 V2 已实测到的救回，至少三分之一能被"短偏离后交回"捕捉，才说明这个价值对象覆盖了学习层的主要收益；低于这个比例，即便通过，仲裁也只能保住基线，拿不到学习层的价值。

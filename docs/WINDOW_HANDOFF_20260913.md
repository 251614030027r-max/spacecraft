## 4. 主线立论:现在成立的是什么

**一句话:** 在一个语义正确、不再人为制造失败的固定 MPC 之外,**仍然存在依赖状态的
任务级决策余量**,而且**没有任何常数能拿到它**。

48 种子、h35、脚本化上层、无训练(`docs/T11_GATE_B_RULING.md`):

| | 完成/48 | 成功均时 | 成功均燃料 |
|---|---:|---:|---:|
| **Pure MPC(固定设定点)** | **32** | 78.8 s | **187.7 N·s** |
| 最好的非零常数 T=20 | 32 | 98.6 s | 277.0 N·s |
| 其余常数 T=40…120 | 18–25 | 更差 | 更差 |
| **逐状态 oracle** | **40** | 91.0 s | **230.9 N·s** |

- 最好的常数 32/48,逐状态 40/48,**差 8 个种子(+25%)**。
- 逐状态在 32 个基线完成的种子上**一律选 T=0**,所以那 32 个上它逐位就是固定设定点;
  燃料 187.7 → 230.9 N·s **完全来自新增的 8 个完成**,不是从已有成绩上扣的。
- **262011 的可行提交集是断开的**({40} 与 {95,100,110},中间 50/60/80 全败),
  两台机器、两个独立网格交叉验证。**阈值型规则表示不了它。**

**必须一起带的两条:**

1. **逐状态 40/48 是 oracle,不是控制器。** T 是知道结果后按种子挑的,是性能上界,
   **永远不能作为主表的一行**。
2. **到今天为止,唯一测过的"学习 vs 基线"对比是负的**(旧下层上 7/12 对 8/12、
   配对燃料贵 40%)。T12 是**第一次**在干净下层上做这个对比。**没出结果前不许
   只讲"接口让它可学"。**

## 5. 已经撤回的(别再用)

| 撤回的说法 | 为什么 |
|---|---|
| "固定设定点让 QP 无解,所以需要上层" | **门控缺陷**造成的假象。修正后 QP 每步都解得出来,同样的种子照样失败。见 `docs/TERMINAL_GATE_DEFECT.md` |
| "学习上层的贡献是保住下层可行性" | 同上。修正后对照组在 262005 上 0 步不可行,照样失败 |
| "2 s 时域看不到 152 s 周期,所以 MPC 结构上不可能等待" | **过强**,滚动时域靠重规划可以无限期保持。正确说法:QP 的目标函数里没有任何一项给"现在等、以后赚"记分,而参考是外生常值——**它不是做不到等,是没有理由选择等**。而且这只证明"要某种上层",**不证明"要学习的上层"** |
| "死种子学会了用负动作长期等待" | 回放证伪,死种子比活种子更少用负动作 |
| "姿态参考是 262006 的症结" | 探针证伪,`aimed` 死得更早 |

**真正的病因**(已实验证实,`docs/T11_INTERFACE_CALIBRATION.md`):接口的
`∂r_ref/∂a0 ≈ −6.5 m/单位动作`,而一个 2 s 决策窗的平动权限只有 **0.094 m**。
注入死种子的动作统计 `a0 ~ N(0.80, 0.09)`,**8/8 完成变 0/8**、燃料涨 10 倍;
加上**提交棘轮** `b_k = max(b_{k−1}, b_k_cmd)` 后 **7/8 恢复**。棘轮零可调常数,
`a=(+1,·)` 的逐位 Pure MPC 地板完好(12 种子,字段与燃料差异全为 0)。

## 6. 本会话最重要的方法论教训

**用户点过我"给自己立论推翻的惯用性"。分清两件事:**

- **便宜地杀死自己的假设 = 工作正常。** 本会话四次推翻(负动作等待、姿态参考、
  §3g 无解论、时间尺度论证),每一次都是在花训练之前用几十分钟的诊断杀掉的。
- **毛病在于:提假设比验假设快,而且用叙事的口气讲还没验的东西。**
  规矩:凡没测过的,文档里标 **【推】**,嘴上说"这是推断"。

**两条硬规矩,都是被现实教出来的:**

1. **交给下层的每条命令,自己先实跑一遍。**
   T12 这一轮因此抓出四个会让整轮白跑的坑:`--horizon` 默认 20(全线基线在 h35)、
   `--parametrization` 默认 `radial_local`、`--phase-time-observation` 默认关
   (**导致评估直接拒绝加载**)、以及我自己按 24+1 推算错的观测维数(**实测 32 维**)。
   现在 manifest 会写出一行可复制的 `evaluation_flags`。
2. **闸门判据写完要自检是不是恒真。**
   我把闸门 B 写成"任何常数追平基线就停",而**基线本身就是常数 T=0**——恒真。
   下层严格执行并停机,白等一轮。正确写法是**最好的常数对逐状态**。
   工具已修(`experiments/summarize_headroom.py`)。

**还有一条提速授权**(`docs/T11_EXECUTION_ORDER.md` §1):
**结果型评估可以并行**,依据是沙箱并行 3–5 进程的结果与下层串行结果在共同 12 个种子上
**逐条一致**。但**耗时数字仍须串行单进程单独跑**。
